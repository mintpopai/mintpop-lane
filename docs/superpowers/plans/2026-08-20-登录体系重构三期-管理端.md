# 登录体系重构三期 · 管理端网页 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 管理端网页从「@logto/browser 直连 Logto 持 access token」切到「服务端 Cookie 会话」，用户管理界面对齐订阅化新模型（删新建用户、列表带邮箱与在期订阅、新增订阅管理），登录体系重构收官。

**Architecture:** 登录改为整页跳服务端 `/oauth2/authorization/logto`，服务端握手完毕种 `lane_session` HttpOnly Cookie 后 302 回来；前端不再持有任何 token——HTTP 客户端去掉 Authorization 注入，同域请求自动携带 Cookie，401 时跳登录入口。身份与角色从 `GET /api/me` 读取（isAdmin 直接看 `me.role`，服务端 403 仍是真正的强制层）。运行时配置收窄到只剩 `apiBaseUrl`。开发模式经 Vite 代理把 `/api`、`/auth`、`/oauth2` 都转给本机服务端，实现全环境同域、零 CORS。

**Tech Stack:** Vue 3 + Element Plus + Pinia + Vitest（现有栈不变）；删除依赖 `@logto/browser`。

**Spec:** `docs/superpowers/specs/2026-08-19-登录体系重构-design.md`（§4 登录流、§8 管理端）

**前置:** 计划一（服务端）、计划二（桌面端）均已合并 main。

## 服务端接口契约（以已合并实现为准，本计划只消费）

| 接口 | 形状 |
|---|---|
| 登录入口 | 浏览器整页跳 `GET /oauth2/authorization/logto`（同域相对路径，不在 /api 前缀下）；服务端握手完毕种 `lane_session` Cookie（HttpOnly、SameSite=Lax、7 天）并 302 到 `lane.auth.admin-frontend-url`；失败 302 `?login_error=1` |
| 登出 | 浏览器整页跳 `GET /auth/logout`（清 Cookie 后 302 回管理端首页） |
| `GET /api/me`（Cookie） | `ApiResponse<{id,email,name,role,subscriptions:[{id,name,agentType,startsAt,endsAt,active}]}>`；HTTP 401 = 未登录/会话失效 |
| 用户 | `GET /api/admin/users?keyword&hasActiveSubscription&pageNo&pageSize`（hasActiveSubscription 可省略= 不筛选）→ `PageResult<AdminUserResponse>`；`PUT /api/admin/users/{id}` body `{status,frontNodeId,landNodeId}`；`DELETE /api/admin/users/{id}`；**POST 已删除**（用户由登录自动建档） |
| AdminUserResponse | `{id,subject,email,name,role,status,frontNodeId,frontNodeName,landNodeId,landNodeName,egressIps,activeSubscriptions:[{id,name,agentType,endsAt}],createdAt,updatedAt}`（无 credentialConfigured） |
| 订阅 | `GET/POST /api/admin/users/{userId}/subscriptions`；`PUT/DELETE /api/admin/subscriptions/{id}`；入参 `{agentType,name,startsAt,endsAt,credential?,remark?}`（更新时 credential 留空=沿用原值）；响应 `{id,userId,agentType,name,startsAt,endsAt,hasCredential,remark,createdAt,updatedAt}` |
| 业务码 | `410006` USER_NOT_FOUND、`410008` SUBSCRIPTION_NOT_FOUND、`110001` PARAM_INVALID（止期不晚于起期等）；401/403 走原生状态码 |
| 时间字段 | `LocalDateTime` 的 ISO 字符串（`2026-09-18T12:00:00`），提交同格式 |

**同域约定**：生产由宿主 nginx 把 `/api`、`/auth`、`/oauth2` 都转给服务端（计划一已写入部署文档）；开发由 Vite 代理承担同样职责，故 Cookie 全程同域，`fetch` 默认的 `same-origin` 凭据策略即可，无需 CORS 配置。**本地开发需在 Logto 应用追加回调地址 `http://localhost:5173/auth/callback`**（经 Vite 代理转给服务端；`{baseUrl}` 按 Host 头解析，Vite 代理默认不改写 Host，回调会正确落回 5173）。

## Global Constraints

- **分支**：在新分支 `refactor/auth-bff-admin` 上实施。
- **前端不持有、不解析任何 token**：无 Authorization 头、无 token 存储；登录态只由 `/api/me` 的成败得出。
- **权限归属**：`isAdmin` 由 `me.role === "ADMIN"` 得出仅供路由与 UI 展示；真正的强制层是服务端 403（http.ts 的 ForbiddenError 机制保留）。
- **凭据纪律**：订阅凭据只在表单提交方向流动，服务端只回传 `hasCredential`；界面上任何地方不回显凭据。
- **枚举镜像**：`AGENT_TYPE { CLAUDE, CODEX }` 等成员名与字符串取值 SCREAMING_SNAKE_CASE、与服务端逐字一致。
- **中文**：注释、UI 文案、提交信息一律简体中文；变量命名沿用本组件既有风格（视图层中文变量名是既有惯例，保持）。
- **命令**：测试 `mise run test-admin`（vitest）；lint `mise run lint-admin`（eslint + vue-tsc，提交前必须过）；构建冒烟 `mise run build-admin`。
- **测试模式**：依赖注入优先——http/fetch/api 都有注入点，测试传假实现，不打模块补丁（现有 spec 的既定风格）。

- [ ] **Step 5: 重写 stores/auth.ts 与其测试**

```ts
import { defineStore } from "pinia";
import { computed, ref } from "vue";
import type { AuthApi } from "../api/auth";
import { UnauthorizedError } from "../api/http";
import type { MeResponse } from "../api/types";

/**
 * 登录态完全由服务端会话 Cookie 承载，前端不持有任何 token。
 * 「我是谁、是不是管理员」都从 /api/me 读；真正的权限强制层是服务端的 403，
 * 这里的 isAdmin 只用于路由与界面展示。
 */
export const useAuthStore = defineStore("auth", () => {
  const me = ref<MeResponse | null>(null);
  const probed = ref(false);

  const authenticated = computed(() => me.value !== null);
  /** null 表示还没探过（探测失败也算没探过，下次导航重试） */
  const isAdmin = computed<boolean | null>(() =>
    probed.value ? (me.value ? me.value.role === "ADMIN" : false) : null,
  );
  const displayName = computed(() => me.value?.name || me.value?.email || "");

  /**
   * 用 /api/me 同步一次登录态。401 = 没登录（返回 false，不抛）；
   * 其它异常原样抛出——网络抖动不能被误判成没登录，否则会平白把人踢去 Logto。
   */
  async function refreshAuthState(api: AuthApi): Promise<boolean> {
    try {
      me.value = await api.me();
      probed.value = true;
      return true;
    } catch (error) {
      if (error instanceof UnauthorizedError) {
        me.value = null;
        probed.value = true;
        return false;
      }
      throw error;
    }
  }

  /** 整页跳服务端登录入口，握手由服务端完成，回来时已带会话 Cookie */
  function signIn(): void {
    window.location.assign("/oauth2/authorization/logto");
  }

  /** 整页跳服务端登出端点，清 Cookie 后 302 回管理端首页 */
  function signOut(): void {
    me.value = null;
    probed.value = false;
    window.location.assign("/auth/logout");
  }

  return { me, authenticated, isAdmin, displayName, refreshAuthState, signIn, signOut };
});
```

```ts
import { runtimeConfig } from "../config/runtime";
import { createAdminApi, type AdminApi } from "./admin";
import { createAuthApi, type AuthApi } from "./auth";
import { createHttpClient, type HttpClient } from "./http";

let http: HttpClient | null = null;
let admin: AdminApi | null = null;
let auth: AuthApi | null = null;

/**
 * 组装层：凭据在 HttpOnly Cookie 里，浏览器自动携带，这里只接「接口前缀」
 * 与「会话失效跳登录」两个运行时依赖。业务代码只依赖接口，测试直接传假实现。
 */
function httpClient(): HttpClient {
  if (!http) {
    http = createHttpClient({
      baseUrl: runtimeConfig().apiBaseUrl,
      // 会话失效就整页跳服务端登录入口。跳转会离开本页，不必等待返回
      onUnauthorized: () => window.location.assign("/oauth2/authorization/logto"),
    });
  }
  return http;
}

export function adminApi(): AdminApi {
  if (!admin) {
    admin = createAdminApi(httpClient());
  }
  return admin;
}

export function authApi(): AuthApi {
  if (!auth) {
    auth = createAuthApi(httpClient());
  }
  return auth;
}
```

```ts
import type { AdminSubscriptionResponse, SubscriptionSaveRequest } from "../api/types";

/** 表单模型。agentType 用 string：回填未知类型时保留原值，避免打开即误改 */
export interface SubscriptionFormModel {
  id: number | null;
  agentType: string;
  name: string;
  startsAt: string;
  endsAt: string;
  /** 留空表示沿用原凭据 */
  credential: string;
  remark: string;
}

export function emptySubscriptionForm(): SubscriptionFormModel {
  return {
    id: null,
    agentType: "CLAUDE",
    name: "",
    startsAt: "",
    endsAt: "",
    credential: "",
    remark: "",
  };
}

export function subscriptionToForm(s: AdminSubscriptionResponse): SubscriptionFormModel {
  return {
    id: s.id,
    agentType: s.agentType,
    name: s.name,
    startsAt: s.startsAt,
    endsAt: s.endsAt,
    // 服务端不回传凭据，回填一律为空；提交时空串即表示不修改
    credential: "",
    remark: s.remark ?? "",
  };
}

export function validateSubscriptionForm(form: SubscriptionFormModel): string[] {
  const errors: string[] = [];
  const name = form.name.trim();
  if (!name) {
    errors.push("套餐名不能为空");
  } else if (name.length > 64) {
    errors.push("套餐名最长 64 个字符");
  }
  if (!form.startsAt) {
    errors.push("起期不能为空");
  }
  if (!form.endsAt) {
    errors.push("止期不能为空");
  }
  // ISO 字符串可按字典序比较；与服务端「止期必须晚于起期」判定一致
  if (form.startsAt && form.endsAt && form.endsAt <= form.startsAt) {
    errors.push("止期必须晚于起期");
  }
  return errors;
}

export function buildSubscriptionPayload(form: SubscriptionFormModel): SubscriptionSaveRequest {
  return {
    agentType: form.agentType as SubscriptionSaveRequest["agentType"],
    name: form.name.trim(),
    startsAt: form.startsAt,
    endsAt: form.endsAt,
    // 空串 = 沿用原值，服务端按空白转 null 处理
    credential: form.credential.trim(),
    remark: form.remark.trim(),
  };
}
```

## 手工验收清单（需本地服务端 + 真实 Logto 租户）

1. Logto 传统 Web 应用追加回调 `http://localhost:5173/auth/callback` → `mise run run-server` + `mise run run-admin` → 打开 5173 任意页 → 自动整页跳 Logto → 登录 → 302 回 5173 且已带会话（管理员账号进入用户列表，MEMBER 账号落 /forbidden）；
2. 用户列表：能看到邮箱列与在期订阅 tag；筛选「无在期订阅」只剩未开通用户；搜索邮箱能命中；
3. 给一个用户「订阅」→ 新建 CLAUDE 订阅（填凭据）→ 列表出现、凭据显示「已录入」；编辑延长止期且凭据留空 → 保存后「已录入」不变（未被清掉）；
4. 编辑用户：只能改状态与节点；邮箱/姓名/Logto id 只读展示；
5. 删除一个 PENDING 注册用户 → 确认文案提及订阅与落地释放，删除成功；
6. 「退出登录」→ 302 回首页 → 再访问任意页重新跳 Logto；
7. 会话过期模拟：服务端换 `LANE_AUTH_SESSION_SECRET` 重启 → 管理端任意操作自动跳登录入口。

## 已知取舍

- **无 SPA 内登录页**：未登录直接整页跳 Logto（与旧版行为一致），登录失败回跳的 `?login_error=1` 参数暂不消费（服务端失败场景极少，后续可加提示）。
- **`isAdmin` 由 `me.role` 得出**：省掉旧版「探 403」的启发式；强制层仍是服务端 403，前端角色仅影响路由与展示。
- **订阅无分页**：单用户订阅量级极小，列表一次拉全。
- **agentType 前端用 string 承载**：与桌面端同一取舍，服务端加新 agent 不逼前端升级（标签缺失时回退显示原始值）。

# 官网中英双语 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `apps/website` 从单语单页站改造成中英双语站，`/` 出中文、`/en/` 出英文，两份都在构建期预渲染成完整 HTML、可被搜索引擎分别收录。

**Architecture:** 引入 `vue-router` + `vite-ssg` + `@unhead/vue`。语言的单一来源是 URL，locale 由路由派生并经 provide/inject 挂在 app 实例上（**不能用模块单例**：vite-ssg 并发预渲染多条路由，模块级可变状态会被别的路由改写）。全部文案集中在 `src/content/copy.ts` 的 `COPY: Record<Locale, Copy>`，中英结构由 `interface Copy` 强制一致。

**Tech Stack:** Vue 3.5.41 · Vite 8.2.1 · vue-router 5.2.0 · vite-ssg 28.3.0 · @unhead/vue 2.1.17 · vitest 4.1.10 · pnpm 11.22.0 · node 26.7.0（版本由根 `mise.toml [tools]` 管）

**Spec:** `docs/superpowers/specs/2026-08-25-website-i18n-design.md`

## Global Constraints

- **回复与文档语言**：本仓库的注释、文档、提交信息一律**简体中文**；标识符一律英文。
- **命令收口 mise**：所有构建/测试/检查走 `mise run <task>`，不直接敲 `pnpm vite`。本计划涉及的四个：`mise run install-website`、`mise run build-website`、`mise run lint-website`、`mise run test-website`。
- **依赖钉死具体版本**：`apps/website/package.json` 现有依赖全部是无 `^` 的精确版本，新增依赖照此办理。
- **`@unhead/vue` 必须钉在 2.x（本计划取 `2.1.17`）**：`vite-ssg@28.3.0` 的 `dependencies` 里是 `@unhead/vue: ^2.1.2`。若应用层装 3.x，会出现**两份 unhead 实例**——应用里 `useHead` 注册的内容不在 vite-ssg 序列化的那一份上，预渲染出来的 HTML 里 head 会是空的，且**不报任何错**。装 `2.1.17`（2.x 最新）能与 vite-ssg 的 `^2.1.2` 去重成同一份。
- **SSR 安全**：构建期（node）没有 `window` / `document` / `navigator` / `localStorage`。任何浏览器 API 只能出现在 `onMounted` 里，不能在模块顶层或 `setup` 同步执行。
- **语言唯一来源是 URL**：`/en`、`/en/**` → `en`，其余 → `zh`。不读 `navigator.language`，不做自动语言跳转。
- **`localStorage` key**：`lane-locale`，只在用户手动切换语言时写入。
- **英文文案不做直译**：沿用 `copy.ts` 顶部的自查原则（「每句话都问『读者看完会想那跟我有什么关系吗』，会就删掉重写」）。
- **TS 约束**：`strict: true` 且 `noUnusedLocals: true` / `noUnusedParameters: true`——不要留未使用的导入或变量，`vue-tsc` 会直接报错。

### Task 1: `formatSize` 语言无关化

`formatSize` 是纯函数且有单测，却在返回值里写死了中文「约」。把语言相关的前缀移出去，前缀由调用方按语言拼。不给它加 locale 参数——那会让一个与语言无关的字节换算函数凭空长出语言依赖。

**Files:**

**Interfaces:**

- Produces: `formatSize(bytes: number): string | null` —— 返回 `"32 MB"` 这样的裸体积，不带任何语言前缀；拿不到有效体积仍返回 `null`。

- [ ] **Step 1: 先改测试，让它失败**

    expect(formatSize(33_554_432)).toBe("32 MB");

```

（`describe("formatSize")` 的第二条 `拿不到有效体积时给 null` 保持不动。）

- [ ] **Step 2: 跑测试确认它失败**

```

- [ ] **Step 3: 改实现**

`apps/website/src/composables/release.ts`：

```ts
/** 字节数转成给人看的近似体积；拿不到有效体积时给 null（调用方不渲染这一段）。
    「约 / ~」这类语言相关的前缀不在这里拼，由调用方按当前语言加，见 copy.ts 的 ui.download.sizePrefix */
export function formatSize(bytes: number): string | null {
  if (!Number.isFinite(bytes) || bytes <= 0) return null;
  return `${Math.round(bytes / 1024 / 1024)} MB`;
}
```

```ts
// 语言的单一来源是 URL：/ 是中文，/en/ 是英文。
// 这里只放不依赖 vue-router 的纯逻辑；provide/inject 那部分见本文件后半（Task 4 补）。
export type Locale = "zh" | "en";

const STORAGE_KEY = "lane-locale";

/** URL → 语言。/enterprise 这类前缀相同的路径不算英文，故不能只用 startsWith("/en") */
export function localeFromPath(path: string): Locale {
  return path === "/en" || path.startsWith("/en/") ? "en" : "zh";
}

/** 语言 → URL。英文带尾斜杠，与 vite-ssg nested 预渲染出的 /en/index.html 形态一致 */
export function localePath(l: Locale): string {
  return l === "zh" ? "/" : "/en/";
}

/** 只在用户手动切换语言时写入；回访时 App.vue 据此把 / 跳到 /en/。
    调用方必须保证在浏览器里执行（onMounted 之后），构建期没有 localStorage */
export function rememberLocale(l: Locale): void {
  localStorage.setItem(STORAGE_KEY, l);
}

/** 读回显式选择过的语言；没存过或存着不认识的值都给 null */
export function savedLocale(): Locale | null {
  const saved = localStorage.getItem(STORAGE_KEY);
  return saved === "zh" || saved === "en" ? saved : null;
}
```

在 `apps/website/src/i18n.ts` **顶部**加 import、**末尾**追加以下内容（Task 2 写的纯函数原样保留）：

```ts
import { computed, inject, provide, ref, watch, type InjectionKey, type Ref } from "vue";
import { useRoute } from "vue-router";
import { COPY, type Copy } from "./content/copy";
```

```ts
const LOCALE_KEY: InjectionKey<Ref<Locale>> = Symbol("locale");

// 在根组件（App.vue）的 setup 里调用一次：locale 挂在 app 实例上（provide），**不做模块单例**——
// vite-ssg 会在同一进程里**并发**预渲染多条路由，模块级可变状态会被其它路由的渲染改写
// （跨请求状态污染：典型症状是中文页序列化出英文 head）。每个 app 实例一份，天然隔离。
export function provideI18n() {
  const route = useRoute();
  const locale = ref<Locale>(localeFromPath(route.path));
  watch(
    () => route.path,
    (p) => (locale.value = localeFromPath(p)),
  );
  provide(LOCALE_KEY, locale);
  return makeI18n(locale);
}

/** 子组件取用（App.vue 已 provide，注入必然成功） */
export function useI18n() {
  const locale = inject(LOCALE_KEY);
  if (!locale) throw new Error("useI18n 必须在 App.vue（provideI18n）之下使用");
  return makeI18n(locale);
}

function makeI18n(locale: Ref<Locale>) {
  const t = computed<Copy>(() => COPY[locale.value]);
  const htmlLang = computed(() => (locale.value === "zh" ? "zh-CN" : "en"));
  return { locale, t, htmlLang };
}
```

const SITE = "https://lane.mintpop.ai";

// head 按语言输出，全部交给 unhead（index.html 只留与语言无关的静态项）：
// - lang / title / description / og / twitter / JSON-LD 随 locale 切换；

      { name: "description", content: description },
      { property: "og:title", content: title },
      { property: "og:description", content: description },
      { property: "og:url", content: SITE + localePath(locale.value) },
      { property: "og:locale", content: locale.value === "zh" ? "zh_CN" : "en_US" },
      { property: "og:image:alt", content: title },
      { name: "twitter:title", content: title },
      { name: "twitter:description", content: description },

        downloadUrl: `${SITE}${localePath(locale.value)}#download`,

## 已知取舍与后续

这些是**有意留下**的，不是漏项：

1. **数组长度中英不一致，TS 抓不到。** `interface Copy` 能保证字段齐全，但 `faq.items` 是 `{q,a}[]`，中文 5 条、英文写成 4 条也能编译通过。spec 明确「不另写运行时测试」，故靠 Task 5 Step 10/11 的产物 grep 与人工验收兜底。若以后觉得不够，加一个比对 `COPY.zh` 与 `COPY.en` 各数组长度的单测即可。
2. **`TheFooter.vue` 的 `new Date().getFullYear()` 在 SSG 下于构建期求值。** 预渲染出的年份是发版当时的年份，跨年后首帧会与客户端算出的值不一致（Vue 会有一条水合警告）。每次发版重新构建即自愈，暂不处理。
3. **桌面端仍是纯中文界面。** 英文页的模拟界面显示英文，展示的是一个尚不存在的界面——这是已确认的取舍，桌面端 i18n 建议单独立项。
4. **`beasties`（vite-ssg 的可选 peer，做关键 CSS 内联）没装。** 不装只是少一项首屏优化，不影响正确性；`pnpm install` 可能提示缺这个可选 peer，属正常。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把前置节点从「一个用户绑死一个」改成「按故障域分散的一组」，并让客户端组成两层 `fallback`——内层救落地机、外层救中转入口。

### 下发契约（**唯一权威，A 与 B 都以此为准**）

`GET /api/link/config` 的 `LinkConfigResponse` 新增一个字段，**`front` / `land` / 其余字段一个都不动**：

```jsonc
{
  "front": { /* mihomo 节点，保留：老客户端只认它 */ },
  "land":  { /* mihomo 节点 */ },
  "frontGroups": [                    // 新增。老客户端忽略；新客户端优先用它
    {
      "failureDomain": "jp.tsdns.top",   // 分组键与三期上报的关联键；**可为 null**，见铁律 4
      "nodes": [ { /* 完整 mihomo 节点定义 */ }, /* … */ ]
    }
  ],
  "expectedEgressIp": "…", "egressTimezone": "…",
  "agentCredentials": [ /* … */ ], "ttlSeconds": 1800
}
```

四条铁律：

1. **`front` 永远有值**，取 `frontGroups[0].nodes[0]`。老客户端只读它，行为与二期前逐字相同。
2. **`failureDomain` 只作接口上的分组键**。桌面端**不得**拿它当 mihomo 组名——生成的配置用户可见可导出，组名里带 `jp.tsdns.top` 等于把机场中转拓扑摊给用户看。组名一律本地生成 `us-front-<下标>`。
3. **`frontGroups` 缺失或为空时，桌面端回退到旧的单 `front` 逻辑**（兼容服务端未升级）。
4. **`failureDomain` 可为 null**，含义是「该组节点尚未解析出故障域」。手工新建的 FRONT 节点永远没有
   `failure_domain`，而手工指定单节点是本期保留的逃生口；服务端不开全局 `JsonInclude(NON_NULL)`，
   该字段为 null 会实打实下发成 `"failureDomain": null`。**桌面端 DTO 必须可空**（`Option<String>`）——
   非可空类型收到 null 会让**整份 `LinkConfigData` 解析失败**，客户端拿不到任何链路配置，是硬故障不是降级
   （`#[serde(default)]` 只兜「字段缺失」，兜不住「字段是 null」）。该组照常下发、照常生成内层组，
   组名本来就是本地生成的 `us-front-<下标>`，不依赖这个值。

### 本期的现实前提（写代码时要记着）

目前只有一家机场，美国节点全在 `jp.tsdns.top` 一个故障域下。所以**外层 fallback 现在是空转的**——它要等第二家机场进来才起作用，届时**不需要改代码**。本期真正兑现的价值是内层：12 台美国落地机互为备份，消掉「`front_node_id` 单选、零重试」这个把一切瞬时抖动放大成硬故障的单点。

private String columnComment(Connection conn, String table, String column) throws Exception {
    try (PreparedStatement ps = conn.prepareStatement(
            "SELECT column_comment FROM information_schema.columns "
          + "WHERE table_schema = ? AND table_name = ? AND column_name = ?")) {
        ps.setString(1, conn.getCatalog());
        ps.setString(2, table);
        ps.setString(3, column);
        try (ResultSet rs = ps.executeQuery()) {
            return rs.next() ? rs.getString(1) : null;

import java.util.regex.Pattern;

/**
 * 按节点名判定它是不是「落地在美国」。
 *
 * 这是启发式：机场命名不规范时会漏判，所以凡是用它做决策的地方都要把判定结果

public final class UsLandingNodes {

    private static final Pattern US_NODE = Pattern.compile("(?i)(\\[US]|United States|美国|🇺🇸)");

    private UsLandingNodes() {
    }

    public static boolean isUsLanding(String nodeName) {
        return nodeName != null && US_NODE.matcher(nodeName).find();
    }
}

    private ProxyNodeDto node(long id, String name, String failureDomain, NodeStatus status) {
        ProxyNodeDto dto = new ProxyNodeDto();
        dto.setId(id);
        dto.setName(name);
        dto.setRole(NodeRole.FRONT);
        dto.setFailureDomain(failureDomain);
        dto.setStatus(status);
        return dto;

    @DisplayName("两个故障域时各取 K 个，跨域分散")

        when(nodeRepository.findAll(NodeRole.FRONT)).thenReturn(List.of(

- [ ] **Step 3: 实现**

`render_kernel_config` 里分两条路：

- `link.front_groups` 为空 → **保持现有代码原样**（单 `front` + `LAND.dialer-proxy = FRONT`）。
- 非空 → 前置节点逐个改名 `us-front-<组下标>-<节点下标>`、`remove("dialer-proxy")`；每组生成一个内层 `fallback` 组；再生成外层 `us-front`；`LAND.dialer-proxy = "us-front"`。

健康检查 URL 需要 lane 的服务端地址——`render_kernel_config` 目前不接收 `base_url`，**加一个参数传进来**（调用点在 `state.rs`，那里已有 base_url）。组的公共字段：

```rust
group.insert(Value::from("type"), Value::from("fallback"));
group.insert(Value::from("url"), Value::from(format!("{base_url}/api/ping")));
group.insert(Value::from("interval"), Value::from(180));
```

> **为什么是 `fallback` 不是 `url-test`**：`url-test` 按延迟择优会频繁切换，每切一次就是一次新握手——与一期「把握手挪出关键路径」的方向正好相反。`fallback` 只在当前节点不可用时才换，保持粘性。这条别改。

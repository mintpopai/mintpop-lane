# Pier 受控终端 · 计划三：打包与分发

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 桌面端产出 macOS arm64 与 Windows x64 安装包（内置 mihomo，员工装完即用），服务端产出 GHCR 镜像并以 compose 部署；两者各有 tag 触发的发版流水线与 GitHub Release。

**Architecture:** mihomo 作为 Tauri sidecar 随安装包分发，运行时从主程序同级目录定位，不再依赖 `MIHOMO_BIN` 环境变量；Logto 与服务端地址在构建期注入为编译期常量，安装包开箱即用。服务端镜像按「context 取仓库根、mise 提供工具链、多阶段构建」的既定流程构建，部署侧只 `pull` 不 `build`。

**Tech Stack:** Tauri 2 打包（`externalBin`）；Docker + BuildKit + GHCR；GitHub Actions；`docker/metadata-action` 打标；`mikepenz/release-changelog-builder-action` 生成变更日志。

**Spec:** `docs/superpowers/specs/2026-08-16-pier-terminal-design.md`

**前置计划:** `2026-08-16-核心链路闭环.md`、`2026-08-17-服务端与身份接入.md`

## Global Constraints

- **目标平台**：macOS arm64（13 及以上）+ Windows x64。**不出 Intel Mac 安装包**，CI 矩阵里不放 Intel mac runner。
- **tag 前缀**：`desktop-v*` / `server-v*`，各组件版本独立计数。workflow 只监听自己的前缀，**绝不用裸 `v*`**；push 到 main 永不触发发版。
- **workflow 命名**：`<动作>-<组件>.yml`（全小写 kebab），`name:` 字段为 Title Case 的「动作 组件」。流水线通知是唯一特例，固定 `action-notify.yml` / `Action Notify`。
- **每个 step 都写 `name:`**，包括 `uses:` 型的。
- **镜像单架构**：只打 runner 本机架构，不加 QEMU、不写 `platforms:`；但 **Buildx 必须保留**（`type=gha` 缓存与 per-Dockerfile ignore 都依赖 BuildKit）。
- **镜像打标一律交给 `docker/metadata-action@v5`**，禁止手写 shell 拼 tag；预发布绝不打 `latest`（靠 `flavor: latest=auto`）。
- **门禁前置**：从代码改动到镜像推出之间，必须存在一处会因 lint/test 失败而中断的关卡。
- **忽略文件一律 `Dockerfile.dockerignore`**，禁止裸 `.dockerignore`；白名单式。
- **compose 只做部署**：文件名固定 `docker-compose.yml`，不写 `version:` 键、不写 `build:` 段；必带 `healthcheck`；镜像 tag 与宿主端口参数化；端口三段式且宿主 IP 钉死 `127.0.0.1`。
- **版本只在根 `mise.toml [tools]` 写一次**；Dockerfile 里唯一允许钉死的版本是 mise 自身（自举例外）。
- **每次发版必须建 GitHub Release**，正文 = annotated tag 注释置顶 + 按提交类型过滤的变更日志，且必须兜底防空。
- **中文**：所有文档、注释、提交信息用简体中文。

- [ ] **Step 1: 写下载脚本**

`scripts/fetch-mihomo.sh`。Tauri 要求 `externalBin` 的文件名带目标三元组后缀：

```bash
#!/usr/bin/env bash
# 下载 mihomo 内核并按 Tauri sidecar 命名规则放好。
# 打包前执行一次即可；产物不入库，由 CI 每次重新下载。
set -euo pipefail

MIHOMO_VERSION="${MIHOMO_VERSION:-v1.19.14}"
OUT_DIR="apps/desktop/src-tauri/binaries"
mkdir -p "$OUT_DIR"

# 目标三元组必须与 rustc 一致，Tauri 据此匹配 sidecar
TRIPLE="$(rustc -vV | awk '/host:/ {print $2}')"

case "$TRIPLE" in
  aarch64-apple-darwin)   ASSET="mihomo-darwin-arm64-${MIHOMO_VERSION}.gz"; EXT="" ;;
  x86_64-pc-windows-msvc) ASSET="mihomo-windows-amd64-${MIHOMO_VERSION}.zip"; EXT=".exe" ;;
  *) echo "不支持的目标平台：${TRIPLE}" >&2; exit 1 ;;
esac

URL="https://github.com/MetaCubeX/mihomo/releases/download/${MIHOMO_VERSION}/${ASSET}"
TMP="$(mktemp -d)"
trap 'rm -rf "$TMP"' EXIT

echo "下载 ${URL}"
curl -fsSL "$URL" -o "${TMP}/${ASSET}"

case "$ASSET" in
  *.gz)  gunzip -c "${TMP}/${ASSET}" > "${OUT_DIR}/mihomo-${TRIPLE}${EXT}" ;;
  *.zip) unzip -q -o "${TMP}/${ASSET}" -d "$TMP" && mv "$TMP"/mihomo*.exe "${OUT_DIR}/mihomo-${TRIPLE}${EXT}" ;;
esac

chmod +x "${OUT_DIR}/mihomo-${TRIPLE}${EXT}"
echo "已就位：${OUT_DIR}/mihomo-${TRIPLE}${EXT}"
```

- [ ] **Step 5: 改写内核路径解析**

在 `lib.rs` 中把 `mihomo_path()` 换成：

```rust
/// 定位 mihomo 内核。
/// 打包后它作为 sidecar 与主程序同级；开发时允许用 MIHOMO_BIN 指向任意二进制。
fn mihomo_path() -> PathBuf {
    if let Ok(custom) = std::env::var("MIHOMO_BIN") {
        return PathBuf::from(custom);
    }

    let name = if cfg!(windows) { "mihomo.exe" } else { "mihomo" };
    std::env::current_exe()
        .ok()
        .and_then(|exe| exe.parent().map(|dir| dir.join(name)))
        .unwrap_or_else(|| PathBuf::from(name))
}
```

```rust
/// 构建期注入的接入配置。CI 打包时通过环境变量提供，
/// 于是安装包开箱即用，员工机上无需设置任何环境变量。
const INJECTED_KEYS: [&str; 4] = [
    "PIER_LOGTO_ISSUER",
    "PIER_LOGTO_CLIENT_ID",
    "PIER_API_RESOURCE",
    "PIER_SERVER_URL",
];

fn main() {
    for key in INJECTED_KEYS {
        println!("cargo:rerun-if-env-changed={key}");
    }
    tauri_build::build()
}
```

- [ ] **Step 2: 读取时优先用编译期常量**

在 `lib.rs` 中加入辅助函数，并让 `oidc_config` 与 `server_base_url` 走它：

```rust
/// 取接入配置：编译期注入的值优先，缺失时回退到运行时环境变量（开发用）
macro_rules! injected {
    ($key:literal) => {
        option_env!($key)
            .map(str::to_string)
            .or_else(|| std::env::var($key).ok())
    };
}

pub fn oidc_config() -> OidcConfig {
    OidcConfig {
        issuer: injected!("PIER_LOGTO_ISSUER").unwrap_or_default(),
        client_id: injected!("PIER_LOGTO_CLIENT_ID").unwrap_or_default(),
        redirect_uri: "pier://callback".to_string(),
        resource: injected!("PIER_API_RESOURCE").unwrap_or_default(),
    }
}

pub fn server_base_url() -> String {
    injected!("PIER_SERVER_URL").unwrap_or_else(|| "http://127.0.0.1:8080".to_string())
}
```

> 这些值不是秘密（issuer、client_id、公开的服务端地址都会出现在网络请求里），编译进二进制没有额外风险；真正的秘密只有服务端持有。

- [ ] **Step 4: 写 Dockerfile**

`apps/server/Dockerfile`。工具链版本只认根 `mise.toml`，Dockerfile 里唯一钉死的是 mise 自身：

```dockerfile
# ---- 构建阶段：干净 slim 底座 + curl 装 mise（官方写法）----
FROM debian:13-slim AS build

# mise 自身版本在此钉死——自举工具无法由 mise.toml 管，这是唯一允许的例外
ENV MISE_VERSION=v2026.6.0
ENV MISE_DATA_DIR=/mise MISE_CONFIG_DIR=/mise MISE_CACHE_DIR=/mise/cache \
    MISE_INSTALL_PATH=/usr/local/bin/mise PATH=/mise/shims:$PATH
# 关掉 mise run 跑 task 前的自动装全部 [tools]，否则会把 rust/node 等无关工具链一并拉下来
ENV MISE_TASK_RUN_AUTO_INSTALL=false

RUN apt-get update \
    && apt-get install -y --no-install-recommends curl git ca-certificates \
    && rm -rf /var/lib/apt/lists/* \
    && curl https://mise.run | sh

WORKDIR /app

# 只装本镜像需要的工具，不要 mise install 全装
COPY mise.toml ./
RUN mise trust && mise install java maven

# 依赖清单与源码分两次 COPY：改源码不会让依赖下载层失效
COPY apps/server/pom.xml ./apps/server/
RUN mise run install-server

COPY apps/server/ ./apps/server/
# 构建命令走 mise task，与本地/CI 单一来源
RUN mise run build-server

# ---- 运行阶段：同样用 mise 提供 JRE，保持版本单一来源 ----
FROM debian:13-slim AS runtime

ENV MISE_VERSION=v2026.6.0
ENV MISE_DATA_DIR=/mise MISE_CONFIG_DIR=/mise MISE_CACHE_DIR=/mise/cache \
    MISE_INSTALL_PATH=/usr/local/bin/mise PATH=/mise/shims:$PATH

RUN apt-get update \
    && apt-get install -y --no-install-recommends curl ca-certificates wget \
    && rm -rf /var/lib/apt/lists/* \
    && curl https://mise.run | sh

WORKDIR /app
# 运行期只需要 java，不装 maven
COPY mise.toml ./
RUN mise trust && mise install java

COPY --from=build /app/apps/server/target/pier-server-*.jar ./server.jar

EXPOSE 8080
# 配置由 compose 以只读卷挂到 /app/config，Spring Boot 会自动读该目录
CMD ["mise", "exec", "--", "java", "-jar", "server.jar", "--spring.config.additional-location=file:/app/config/"]
```

> 运行阶段没有直接用 `eclipse-temurin:25-jre` 这类带运行时的底座，是为了守住「版本只在根 `mise.toml` 写一次」。代价是镜像体积比 JRE 专用底座大，可接受；若将来体积成为问题，正确的收敛方式是 jlink 裁剪运行时，而不是把版本号搬进 Dockerfile。

- [ ] **Step 1: 写 compose**

`deploy/docker-compose.yml`：

```yaml
# 部署：拉 GHCR 已发布镜像运行；本地构建镜像用 mise run image-server，不归 compose 管
# 只监听 127.0.0.1，对外访问由宿主 nginx / cloudflared 反代到这个端口
services:
  server:
    image: ghcr.io/yuebai-blast/pier-server:${SERVER_TAG:-latest}
    container_name: pier-server
    restart: unless-stopped
    ports:
      # 宿主 IP 钉死 127.0.0.1，宿主端口参数化，容器端口固定
      - "127.0.0.1:${SERVER_PORT:-8081}:8080"
    environment:
      SPRING_PROFILES_ACTIVE: prod
    volumes:
      # 含节点与席位凭据，只读挂载，不进镜像
      - ./application-prod.yaml:/app/config/application-prod.yaml:ro
    healthcheck:
      test: ["CMD-SHELL", "wget -qO- http://127.0.0.1:8080/actuator/health >/dev/null 2>&1 || exit 1"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 30s
```

> healthcheck 里的 `127.0.0.1` 是**容器内部**探活自己，与上面宿主侧的监听地址是两回事。

## Task 5: 可复用质量门禁

CI 与发版都要跑同一套检查，抽成可复用 workflow，避免两处定义漂移。

**Files:**
- Create: `.github/workflows/quality.yml`

**Interfaces:**
- Consumes: `mise run lint-desktop`、`mise run test-desktop`、`mise run test-server`
- Produces: 可被 `uses: ./.github/workflows/quality.yml` 调用的门禁

- [ ] **Step 1: 写可复用 workflow**

```yaml
name: Quality

on:
  workflow_call:

jobs:
  desktop:
    name: 桌面端质量门禁
    runs-on: macos-14
    steps:
      - name: 检出代码
        uses: actions/checkout@v4

      - name: 安装工具链
        uses: jdx/mise-action@v4

      - name: 安装前端依赖
        run: mise run install-desktop --frozen

      - name: 检查 Rust 代码
        run: mise run lint-desktop

      - name: 跑 Rust 测试
        run: mise run test-desktop

  server:
    name: 服务端质量门禁
    runs-on: ubuntu-latest
    steps:
      - name: 检出代码
        uses: actions/checkout@v4

      - name: 安装工具链
        uses: jdx/mise-action@v4

      - name: 跑服务端测试
```

## Task 7: 服务端发版

**Files:**
- Create: `.github/workflows/release-server.yml`

**Interfaces:**
- Consumes: `quality.yml`、`apps/server/Dockerfile`
- Produces: `server-v*` tag 触发 → GHCR 镜像 + GitHub Release

- [ ] **Step 1: 写 workflow**

```yaml
name: Release Server

on:
  push:
    tags: ["server-v*"]
  workflow_dispatch:

concurrency:
  group: release-server
  cancel-in-progress: false

env:
  IMAGE: ghcr.io/${{ github.repository_owner }}/pier-server

jobs:
  quality:
    name: 发版前质量门禁
    uses: ./.github/workflows/quality.yml

  image:
    name: 构建并推送镜像
    needs: quality
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write
    steps:
      - name: 检出代码
        uses: actions/checkout@v4

      - name: 设置 Buildx
        uses: docker/setup-buildx-action@v3

      - name: 登录 GHCR
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: 计算镜像标签
        id: meta
        uses: docker/metadata-action@v5
        with:
          images: ${{ env.IMAGE }}
          tags: |
            type=semver,pattern={{version}},value=${{ github.ref_name }},match=server-v(.+)
            type=sha,enable=${{ github.ref_type != 'tag' }}
          flavor: |
            latest=auto

      - name: 构建并推送
        uses: docker/build-push-action@v6
        with:
          context: .
          file: apps/server/Dockerfile
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          labels: ${{ steps.meta.outputs.labels }}
          cache-from: type=gha
          cache-to: type=gha,mode=max

  github-release:
    name: 建立 GitHub Release
    needs: image
    if: github.ref_type == 'tag'
    runs-on: ubuntu-latest
    permissions:
      contents: write
    steps:
      - name: 检出代码
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: 解析上一版同前缀 tag
        id: prev
        env:
          TAG: ${{ github.ref_name }}
        run: |
          prev="$(git tag -l 'server-v*' --sort=-v:refname \
            | awk -v cur="$TAG" 'f { print; exit } $0 == cur { f = 1 }')"
          if [ -z "$prev" ]; then
            prev="$(git rev-list --max-parents=0 HEAD | tail -1)"
          fi
          echo "from=$prev" >> "$GITHUB_OUTPUT"
          # 标题里的版本号要去掉 server-v 前缀，在这里算好，不在表达式里做字符串处理
          echo "version=${TAG#server-v}" >> "$GITHUB_OUTPUT"

      - name: 生成变更日志
        id: changelog
        uses: mikepenz/release-changelog-builder-action@v6
        with:
          fromTag: ${{ steps.prev.outputs.from }}
          toTag: ${{ github.ref_name }}
          configurationJson: |
            {
              "mode": "COMMIT",
              "template": "#{{CHANGELOG}}",
              "label_extractor": [
                {
                  "pattern": "^(feat|fix|perf|refactor|revert|build|chore|ci|docs|style|test)[^:]*:.*",
                  "target": "$1",
                  "on_property": "title",
                  "method": "replace"
                }
              ],
              "categories": [
                { "title": "### 新功能", "labels": ["feat"] },
                { "title": "### 问题修复", "labels": ["fix"] },
                { "title": "### 性能优化", "labels": ["perf"] },
                { "title": "### 重构", "labels": ["refactor"] },
                { "title": "### 回滚", "labels": ["revert"] }
              ]
            }
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}

      - name: 组装 Release 正文
        env:
          TAG: ${{ github.ref_name }}
          CHANGELOG: ${{ steps.changelog.outputs.changelog }}
        run: |
          : > notes.md
          # 只有 annotated tag 才有注释；轻量 tag 的 %(contents) 会错把 commit 信息当注释
          if [ "$(git cat-file -t "$TAG")" = "tag" ]; then
            git tag -l --format='%(contents)' "$TAG" >> notes.md
            printf '\n\n' >> notes.md
          fi
          printf '%s\n' "$CHANGELOG" >> notes.md
          # 兜底：注释为空且提交全被过滤时，正文会整篇空白
          if [ -z "$(tr -d '[:space:]' < notes.md)" ]; then
            echo "- 本次无面向用户的变更" > notes.md
          fi

      - name: 发布 Release
        uses: softprops/action-gh-release@v2
        with:
          name: Pier server v${{ steps.prev.outputs.version }}
          body_path: notes.md
```

> monorepo 的 Release 标题必须带组件名区分，否则分不清是哪个组件发版；默认标题是 tag 名（`server-v0.1.0`），不友好，因此显式设 `name`。

- [ ] **Step 2: 写发版脚本**

`scripts/release.sh`——两个组件共用一份，组件名作第一个参数：

```bash
#!/usr/bin/env bash
# 发版：校验 → 打 tag → 推送。由 tag 触发对应组件的发版流水线。
set -euo pipefail

COMPONENT="$1"
ARG1="${2:-}"
ARG2="${3:-}"

# 单个参数时按形状消歧：像版本号就当版本号，否则当更新说明
VERSION=""
NOTES=""
if [ -n "$ARG2" ]; then
  VERSION="$ARG1"; NOTES="$ARG2"
elif [ -n "$ARG1" ]; then
  if printf '%s' "$ARG1" | grep -qE '^v?[0-9]+\.[0-9]+\.[0-9]+(-[0-9A-Za-z.-]+)?$'; then
    VERSION="$ARG1"
  else
    NOTES="$ARG1"
  fi
fi

# 这一次 fetch 同时供「自动算版本号」与「main 落后检查」复用
git fetch origin main --tags

if [ -z "$VERSION" ]; then
  # 用 git 内置版本序取最新稳定版再 patch+1。禁止 sort -V：macOS 的 BSD sort 不支持
  latest="$(git tag -l "${COMPONENT}-v*" --sort=-v:refname \
    | grep -E "^${COMPONENT}-v[0-9]+\.[0-9]+\.[0-9]+$" | head -1)"
  if [ -z "$latest" ]; then
    VERSION="v0.1.0"
  else
    base="${latest#"${COMPONENT}"-v}"
    major="${base%%.*}"; rest="${base#*.}"; minor="${rest%%.*}"; patch="${rest#*.}"
    VERSION="v${major}.${minor}.$((patch + 1))"
  fi
fi

[ "${VERSION#v}" = "$VERSION" ] && VERSION="v${VERSION}"
TAG="${COMPONENT}-${VERSION}"

# 任一校验不过即中止，绝不打 tag
printf '%s' "$VERSION" | grep -qE '^v[0-9]+\.[0-9]+\.[0-9]+(-[0-9A-Za-z.-]+)?$' \
  || { echo "版本号格式非法：${VERSION}" >&2; exit 1; }
[ "$(git rev-parse --abbrev-ref HEAD)" = "main" ] \
  || { echo "只能在 main 分支发版" >&2; exit 1; }
[ -z "$(git status --porcelain)" ] \
  || { echo "工作区不干净，先提交或暂存改动" >&2; exit 1; }
git rev-parse -q --verify "refs/tags/${TAG}" >/dev/null \
  && { echo "tag 已存在：${TAG}" >&2; exit 1; }
[ -z "$(git rev-list HEAD..origin/main)" ] \
  || { echo "本地 main 落后于 origin/main，先 pull" >&2; exit 1; }

if [ -n "$NOTES" ]; then
  git tag -a "$TAG" -m "$NOTES"    # annotated：注释会被置顶到 Release 正文
else
  git tag "$TAG"
fi

git push origin main && git push origin "$TAG"
echo "已发版：${TAG}"
```

```bash

```

> 版本号纯由 git tag 承载，没有需要同步修改的版本号文件，因此跳过「改版本号 + 提交」这一步。若将来桌面端要让 `package.json` 的 `version` 跟随，用 `pnpm version <X.Y.Z> --no-git-tag-version --allow-same-version` 修改后再打 tag，不要手写 `sed` 改 JSON。

## 遗留事项

- **代码签名与公证**：macOS 未签名的 `.dmg` 会被 Gatekeeper 拦截，Windows 未签名会弹 SmartScreen。需要 Apple Developer ID 与 Windows 代码签名证书，属采购与配置事项，不在本计划内。

- **私有镜像拉取**：GHCR 私有包需要部署机 `docker login`，若改为公开包则免登录，按公司策略定。

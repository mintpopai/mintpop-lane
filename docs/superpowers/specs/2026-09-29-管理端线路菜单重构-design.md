# 管理端「线路」菜单重构设计

## 背景与目标

现在的「节点池」页面把第一跳和第二跳做成页面内的两个页签。第一跳页签的主体是一张平铺的节点表，订阅只作为筛选 chip 和一块常驻的额度面板出现。实际运营时关心的是**机场 → 订阅**这一层：额度、到期、名额、拉取是否正常。至于某个订阅下有哪些节点，只在排查时才需要看。

本次重构的目标：

1. 左侧菜单增加分组「线路」，下面放两个子菜单「机场订阅」「落地节点」，取代页面内页签。
2. 「机场订阅」页按机场分 tab，主体是订阅表。节点下沉到订阅详情页。
3. 独立的「机场」菜单并进「机场订阅」页。
4. 管理端界面文案统一去掉「第一跳 / 第二跳」的说法。

**不改后端。** 订阅响应本身带 `airportId/airportName`，按机场分组、详情页按 id 过滤，都用现有接口在前端完成。

## 1. 菜单与路由

侧栏：

```
用户
换机申请
线路              ← 分组标题，不可点、始终展开
  机场订阅
  落地节点
套餐
企业
链路健康
全局配置
```

- 「线路」只是标题，不可点也不可折叠。当前页属于它下面时，子菜单高亮，标题同时加深一档。
- 删除独立的「机场」菜单。

路由（挂在 `AppLayout` 下）：

| 路径 | 名称 | 页面 |
|---|---|---|
| `/lines/airports` | `AIRPORT_SUBSCRIPTIONS` | `AirportSubscriptionsView`，当前 tab 记在 `?airport=<id>` |
| `/lines/airports/subscriptions/:id` | `SUBSCRIPTION_DETAIL` | `SubscriptionDetailView`，侧栏高亮「机场订阅」 |
| `/lines/land-nodes` | `LAND_NODES` | `LandNodesView` |
| `/nodes`、`/airports` | — | 重定向到 `/lines/airports` |

原有路由名 `NODES`、`AIRPORTS` 删除。`NodesView.vue`、`AirportsView.vue` 及它们的 spec 删除，内容拆进上面三个新页面。`AirportFormModal`、`SubImportModal`、`AirportSubscriptionEditModal`、`AirportSubscriptionAuditModal`、`NodeFormModal`、`NodeProbeModal`、`ConfirmDialog` 等弹窗全部复用。

「机场订阅」子菜单在详情页也要高亮。实现上用路由 `meta` 标明所属菜单，或者按路径前缀判断，不依赖 `RouterLink` 的精确匹配。

## 2. 机场订阅页（`AirportSubscriptionsView`）

```
机场订阅                                   [尽调] [新建机场]
共 3 家机场 · 5 个订阅 · 主用名额 12 / 45。订阅额度跑满会让整批节点同时失效。

 taishan 2 │ 某机场B 1 │ 某机场C 0          ← ViewTabs，一个机场一个 tab，数字＝订阅数
─────────────────────────────────────────
官网 ↗ · 备注 · 主用名额 0 / 30            编辑机场  删除机场   [导入订阅]
订阅名 │ 账号 │ 带宽 │ 主用名额 │ 流量用量 │ 到期 │ 最近拉取     ← 整行可点进详情
```

- **数据**：并发请求 `listAirports()` 和 `listAirportSubscriptions()`，订阅按 `airportId` 分组。tab 上的数字是该机场的订阅数（用前端分组后的结果计数）。
- **页头**：放页面级操作「尽调」和「新建机场」。副题写机场数、订阅数、全站主用名额汇总，外加一句额度风险提醒。
- **机场信息条**（tab 下方）：当前机场的官网（新窗口打开）、备注、主用名额汇总。操作有「编辑机场」「删除机场」「导入订阅」。
  - 「导入订阅」打开 `SubImportModal`，并预选当前机场。`SubImportModal` 为此新增一个可选属性 `defaultAirportId?: number`，传入且确为现存机场时用它作为所属机场的初值（不叫 `airportId`：组件里已有同名的所选机场状态）。
  - 删除机场时，如果机场下还有订阅，服务端会拒绝（410053），前端直接弹出服务端的中文提示。
- **订阅表**：取代原来的常驻额度面板，每个订阅占一行，列如下：
  - 订阅名
  - 账号
  - 带宽（Mbps）
  - 主用名额（`primaryUsed / primaryCapacity`）
  - 流量用量：进度条加百分比，算法沿用原 `quotaPercent`，结果封顶 100。机场没提供额度头时写「未提供」，**不显示成 0%**。
  - 到期
  - 最近拉取：如果 `fetchFailedSince` 非空，这一格显示红色的「拉取失败」，悬停提示「自 <时间> 起：<lastFetchError>」。
  - 整行可点击，跳到 `SUBSCRIPTION_DETAIL`。没有操作列。
  - 整行可点击也要照顾键盘操作：订阅名渲染成 `RouterLink`，同时整行响应点击。
- **选中哪个 tab**：`?airport=` 能对上现存的机场就选它，否则选第一家。切 tab 时用 `router.replace` 更新 query，不往历史栈里压记录。当前机场被删除后，回落到第一家。
- **空态**：
  - 一家机场都没有：显示「还没有机场。先新建机场，再导入它的订阅。」，配「新建机场」按钮。此时不渲染 tab。
  - 当前机场没有订阅：显示「这家机场还没有订阅。」，配「导入订阅」按钮。
- **加载失败**：交给 `DataCard` 的 error 态，和其他页面一致。

## 3. 订阅详情页（`SubscriptionDetailView`）

```
← 机场订阅 / taishan
taishan                               重新拉取  编辑  删除订阅
机场 · 账号 · 订阅链接（打码） · 带宽 · 主用名额 · 流量用量 · 到期 · 最近拉取
⚠ 拉取失败，自 … 起：…          ← 仅在拉取失败时出现
备注
节点（12）
节点名 │ 协议 │ 地址 │ 故障域 │ 密码 │ 更新时间 │ 编辑
```

- **数据**：并发请求 `listAirportSubscriptions()` 和 `listNodes()`，按 `id` 找到订阅，节点按 `role === "FRONT" && airportSubscriptionId === id` 过滤。**不新增后端接口。**
- **面包屑**：「机场订阅」回到 `AIRPORT_SUBSCRIPTIONS`，`query.airport` 取该订阅的 `airportId`。
- **订阅信息**：展示 `AirportSubscriptionResponse` 的全部字段。订阅链接只显示打码形态 `subUrlMasked`。流量的展示规则同第 2 节。
- **订阅操作**：
  - 「重新拉取」打开 `SubImportModal`，传入 `group`。
  - 「编辑」打开 `AirportSubscriptionEditModal`。
  - 「删除订阅」弹出确认框，文案沿用原来的，说明节点会一并删除。服务端返回 410013（订阅仍被引用）时直接弹出服务端的提示。删除成功后跳回机场订阅页，并选中该订阅所属机场的 tab。
  - 任一弹窗保存后都重新加载数据。
- **节点表**：列同原第一跳节点表，只去掉「订阅」列。故障域的展示规则不变。操作只有「编辑」，打开 `NodeFormModal`，`role` 传 `"FRONT"`。节点没有删除入口，因为订阅刷新会把手删的节点对齐回来。
- **订阅不存在**：`:id` 找不到对应订阅时，显示「订阅不存在或已被删除。」，附返回机场订阅页的链接。
- **空节点**：「这个订阅里还没有节点。」，并提示可以点「重新拉取」。

## 4. 落地节点页（`LandNodesView`）

把原「落地」页签的内容原样迁过来：

- 页头：标题「落地节点」，放「新建节点」。副题写落地节点总数，说明按容量分配。
- 状态下拉筛选（全部 / 启用 / 停用），空态区分「一个都没有」和「筛出来为空」。
- 表格列与操作不变：检测、编辑、删除。删除时服务端返回 410003（仍被用户引用）的话，直接弹出服务端提示。
- 删掉原来 `currentRole === 'FRONT'` 的全部分支。

## 5. 管理端文案改名

只改管理端的**界面文案**。代码标识符（`FRONT`/`LAND`、`NodeRole` 等）、代码注释、服务端、用户控制台、桌面端和官网都不在范围内。

| 位置 | 现在 | 改为 |
|---|---|---|
| `api/types.ts` `NODE_ROLE_LABELS` | 第一跳（出国） / 第二跳（落地） | 机场订阅 / 落地节点 |
| `UsersView` 列头 | 第一跳 | 机场订阅 |
| `UserDetailView` 区块标题 | 第一跳（机场订阅） | 机场订阅 |
| `UserDetailView` 提示 | 已分配第一跳，用户下次建立链路时生效 | 已分配机场订阅，用户下次建立链路时生效 |
| `UserDetailView` 提示 | 已取消第一跳分配 | 已取消机场订阅分配 |
| `UserDetailView` 空态 | 未分配第一跳。… | 未分配机场订阅。… |
| `UserDetailView` 确认框标题 | 取消第一跳分配 | 取消机场订阅分配 |
| `UserDetailView` 确认框正文 | …将没有第一跳，直到重新分配 | …将没有机场订阅线路，直到重新分配 |
| `SettingsView` | 第一跳线路的全局参数 | 机场订阅线路的全局参数 |
| `SettingsView` | 作为第一跳候选 | 作为分配候选 |

实施时再在管理端 `src/` 里全量 grep 一遍「第一跳」「第二跳」，确保界面文案（模板文本、字符串字面量）没有遗漏。注释里的保留。

## 6. 测试与验证

- **拆分单测**：原 `NodesView.spec`、`AirportsView.spec` 的断言按归属迁到三个新页面的 spec 里。
- **新增用例**：
  - tab 与 `?airport=` 双向同步；query 无效时选第一家；当前机场被删后回落到第一家。
  - 订阅按机场正确分组，tab 计数正确。
  - 流量「未提供」不显示 0%；拉取失败行显示红色状态。
  - 点击订阅行跳到详情页；「导入订阅」预选当前机场（`SubImportModal` 的 `defaultAirportId` 属性）。
  - 详情页：节点只含本订阅的；订阅不存在时显示提示；删除订阅后跳回对应机场的 tab。
  - 落地节点页：状态筛选与两种空态。
- **更新单测**：
  - `router/index.spec`：新路由、`/nodes` 和 `/airports` 重定向。
  - `AppLayout.spec`：「线路」分组；「机场订阅」在列表页和详情页都高亮；删除了「机场」菜单。
  - 涉及改名文案的断言同步更新。
- **门禁**：`mise run lint-admin`（eslint、prettier、vue-tsc）、`mise run test-admin`、`mise run build-admin` 全部通过。
- **真实页面检查**：用 Claude in Chrome 在真浏览器里检查以下页面：
  - 侧栏分组与高亮
  - 机场订阅页：多 tab、空机场、拉取失败行、额度未提供
  - 订阅详情页：正常、不存在
  - 落地节点页

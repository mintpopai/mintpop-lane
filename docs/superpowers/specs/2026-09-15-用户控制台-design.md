# 用户控制台（console）：自助购买套餐

> 日期：2026-09-15 · 状态：已确认，待实施
> 涉及：`apps/console`（新增）、`apps/server`、`apps/admin`、仓库级工程接入

## 一、背景

现在普通用户拿不到任何自助入口：套餐由管理员在管理端手工分配（`POST /api/admin/users/{id}/subscriptions`），收款在系统之外完成，用户侧只有桌面端。服务端也没有面向普通用户的套餐、订单、支付接口，`plan` 表只有名称、agent 类型、时长、价格、币种、上架，`subscription` 没有订单与支付概念。

目标：新增第四个组件 **用户控制台**，让用户登录后自己挑套餐、付款，付款后系统自动建出一条「待开通」订阅，管理员在管理端填起期即完成开通。

## 二、已确认的决策

1. **履约到「自动建订阅」为止**：付款成功即按套餐快照建一条 `subscription`，**起止时间为空**（待开通）。起期永远由管理员在管理端填，系统不猜、不接续、不叠加。席位凭据（Claude 只能走管理员 OAuth 签发）与落地节点分配仍是管理员动作。
2. **同事务履约**：条件 UPDATE 把订单置 PAID 与 INSERT 订阅在同一事务；建订阅只是本库一次插入，不引入 RECHARGING 中间态、租约锁与履约审计表。
3. **支付照搬 mintpop-shop**：Stripe PaymentIntent + client_secret 内嵌支付；前端展示微信 / 支付宝 / 银行卡三张卡片，后端只有 `stripe` 一个通道；**按套餐币种收款**（USD / CNY），币种不再是配置项。
4. **下单不填任何东西**：选套餐即付。席位账号邮箱、企业归属由管理员开通时填。
5. **第一版页面**：我的订阅、购买套餐、我的订单、支付页、结果页，加登录 / 登录失败两个闸门页。
6. **登录页**照管理端，右侧带子底色换成品牌主色 `#17d1a7`，文字与气泡相应换成深墨 / 白。
7. **域名** `console.lane.mintpop.ai`，与管理端同一种「同域分路径」部署形态。

## 三、非目标

- 不做退款、不做自动续费（Stripe Subscription）、不做发票。
- 不做管理端的订单列表页：管理员靠飞书通知 + 用户详情页的「待开通」徽标与备注里的订单号定位。
- 不改桌面端。
- 不给用户开放改起期、改席位账号的入口。

## 四、总体架构

```
浏览器 ── console.lane.mintpop.ai ──▶ console 容器（nginx）
                                        ├── /            静态 SPA
                                        ├── /api/**      ─┐
                                        ├── /auth/**      ├─▶ server:8080
                                        └── /oauth2/**   ─┘
Stripe ── POST /api/v1/payment/webhook/stripe ──▶ 宿主入口 ──▶ 任一前端容器的 nginx ──▶ server
```

- 登录握手复用现有服务端 OIDC 流程：`OidcLoginSuccessHandler` 用相对路径 302 回「请求到达的 Host」，console 域名天然各回各的，**服务端零改动**，只需在 Logto 登记新域名的回调地址。
- 用户侧接口全部落在 `/api/**`，`SecurityConfig` 现有规则「`/api/**` 登录即可」直接覆盖；只有 webhook 路径要加 `permitAll`。
- 角色判断：console 路由守卫只判「已登录」，不判 `isAdmin`；管理员账号也能用 console 买套餐。
- 账号状态：`SessionAuthFilter` 对非 ACTIVE 用户装配 `ROLE_RESTRICTED`，`/api/**` 仍放行。**下单接口自己校验用户 ACTIVE**，非 ACTIVE 回 `USER_NOT_ACTIVE`；查看订阅与订单不限制。

## 五、数据模型（Flyway V16）

### 5.1 新表 `plan_order`

表名避开 SQL 保留字 `order`。每列带中文注释。

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT PK AUTO | |
| `order_no` | VARCHAR(32) NOT NULL UNIQUE | 订单号：`LN` + `yyyyMMddHHmmss` + 6 位随机数字，给用户看、也是 Stripe metadata 里的 `orderId` |
| `user_id` | BIGINT NOT NULL，FK → `app_user(id)` | 买家 |
| `plan_id` | BIGINT NOT NULL | 所购套餐，弱引用不设外键（套餐硬删后允许悬空） |
| `name` | VARCHAR(64) NOT NULL | 套餐名快照 |
| `agent_type` | VARCHAR(16) NOT NULL | 快照 |
| `plan_duration_days` | INT NOT NULL | 快照 |
| `plan_price` | DECIMAL(10,2) NOT NULL | 快照，展示用 |
| `plan_currency` | VARCHAR(8) NOT NULL | 快照 |
| `amount_minor` | BIGINT NOT NULL | 应付金额，最小货币单位整数（USD / CNY 均为 2 位小数：`price × 100`），下单时定死，入账校验与 Stripe 请求都用它 |
| `status` | VARCHAR(16) NOT NULL | `PENDING` / `PAID` / `CANCELLED` / `EXPIRED` / `FAILED` |
| `payment_provider` | VARCHAR(16) NULL | 固定 `stripe`；未发起支付为空 |
| `payment_trade_no` | VARCHAR(64) NULL | Stripe PaymentIntent id；发起支付即落，`client_secret` 不入库 |
| `paid_at` | DATETIME NULL | 入账时刻（UTC） |
| `subscription_id` | BIGINT NULL | 履约建出的订阅 id，PAID 后必有；弱引用 |
| `created_at` / `updated_at` | DATETIME | 库默认值维护，实体上 `insertStrategy = NEVER, updateStrategy = NEVER` |

索引：`idx_plan_order_user (user_id, created_at)`。

### 5.2 改表 `subscription`

`starts_at`、`ends_at` 由 NOT NULL 改为 **NULL**，列注释补「空表示待开通，由管理员填起期后生效」。两列要么同空要么同有值，由服务层保证。

### 5.3 枚举

- 新增 `OrderStatus`：`PENDING`（待支付）、`PAID`（已支付，履约已完成，终态）、`CANCELLED`（用户取消）、`EXPIRED`（超时未付）、`FAILED`（支付失败，可续付）。
- `Currency` 增加 `minorUnitScale()`：USD、CNY 都返回 2。新币种必须显式给值，不许默认。
- `BizCodeEnum` 开 **51 段（用户自助）**：

| 码 | 名 | 文案 |
|---|---|---|
| 510001 | `PLAN_NOT_AVAILABLE` | 套餐不存在或已下架 |
| 510002 | `ORDER_NOT_FOUND` | 订单不存在 |
| 510003 | `ORDER_NOT_PAYABLE` | 订单当前不可支付 |
| 510004 | `ORDER_NOT_CANCELLABLE` | 订单当前不可取消 |
| 510005 | `PAYMENT_NOT_CONFIGURED` | 支付功能未配置 |
| 510006 | `PAYMENT_GATEWAY_ERROR` | 支付网关异常，请稍后重试 |
| 510007 | `USER_NOT_ACTIVE` | 账号当前不可购买 |

管理段追加 `410041 SUBSCRIPTION_NOT_ACTIVATED`「订阅尚未开通，请先填写起期」（凭证签发入口用）。

### 5.4 待开通订阅的语义落点

- `SubscriptionDto.isActiveAt(now)`：起止任一为空返回 false。
- `/api/me`、链路凭据下发（`LinkServiceImpl`）、管理端「在期订阅」聚合（`AdminUserServiceImpl`）都经 `isActiveAt`，待开通自然不算在期、不下发凭据。
- `CredentialIssueServiceImpl`：签发前若 `endsAt == null` 抛 `SUBSCRIPTION_NOT_ACTIVATED`。
- `AdminSubscriptionServiceImpl.isCredentialStale`：止期为空返回 false。
- `AdminSubscriptionServiceImpl.update`：`startsAt` 仍必填，填了就按快照时长算止期——这就是「开通」动作本身，不新增接口。
- 管理端手工分配（create）行为不变，起期留空仍默认「分配当下」。
- 自助购买建出的订阅：`remark` 固定写 `自助购买，订单 LNxxxxxxxxxxxxxxxxxxxx`，`accountEmail` / `enterpriseId` / `credential` 全空。

## 六、服务端接口

全部返回 `ApiResponse<T>`，HTTP 恒 200，`code === 0` 成功；`@AuthenticationPrincipal Long userId` 取当前用户。新包位置：`controller/`（不进 `admin` 子包）、`service/`、`repository/`、`mapper/`、`entity/`、`request/`、`response/`。

### 6.1 套餐

| 接口 | 说明 |
|---|---|
| `GET /api/plans` | 上架（`enabled = true`）套餐列表，返回 `id / name / agentType / durationDays / price / currency`，**不含 remark**（那是管理员内部备注）。按 agentType、durationDays 排序。 |

### 6.2 订单

| 接口 | 说明 |
|---|---|
| `POST /api/orders` `{ planId }` | 套餐须存在且上架（否则 `PLAN_NOT_AVAILABLE`），用户须 ACTIVE（否则 `USER_NOT_ACTIVE`）。写快照与 `amount_minor`，状态 PENDING。返回 `{ orderNo, amountMinor, currency }`。 |
| `GET /api/orders` | 本人订单按创建倒序，最多返回 100 条（第一版不分页）。入口先对本人超时的 PENDING / FAILED 单做懒惰过期。返回字段：`orderNo, name, agentType, planDurationDays, planPrice, planCurrency, amountMinor, status, paidAt, subscriptionId, createdAt`。 |
| `GET /api/orders/{orderNo}` | 本人单笔，同样先懒惰过期。别人的单一律 `ORDER_NOT_FOUND`。 |
| `POST /api/orders/{orderNo}/cancel` | 仅 PENDING / FAILED 可取消（否则 `ORDER_NOT_CANCELLABLE`），条件 UPDATE 置 CANCELLED；已有 PaymentIntent 则事务提交后尽力而为 `cancel`，失败只记日志。 |

**订单懒惰过期**：无定时任务。`order.expire-minutes` 默认 30；读到超时未付订单的入口（列表、单笔、发起支付、verify）顺手用条件 UPDATE（`status IN (PENDING, FAILED)`）置 EXPIRED，并尽力撤 Stripe 侧 intent。

### 6.3 支付

| 接口 | 说明 |
|---|---|
| `GET /api/payment/checkout-info` | `{ methods: ["stripe"], stripePublishableKey }`；支付未配置时 `methods` 为空数组、key 为 null，前端据此禁用支付入口（优雅降级，不启动失败）。 |
| `POST /api/payment/orders/{orderNo}/intent` | 归属校验 → 状态须 PENDING / FAILED → 懒惰过期拦截 → 无 `payment_trade_no` 则创建 PaymentIntent 并落 id，有则 `retrieve` 复用（Stripe 侧已 canceled 说明本单已被取消或过期撤单，回 `ORDER_NOT_PAYABLE`）。返回 `{ orderNo, clientSecret, amountMinor, currency, productName, expireRemainingSeconds }`。 |
| `POST /api/payment/orders/verify` `{ orderNo }` | 归属校验；若本地已是终态直接回状态；否则向 Stripe `retrieve`，`succeeded` 走 `settlePaid`；其它状态不动本地订单（`payment_failed` 的 FAILED 由 webhook 置，同一个 intent 可继续重试付款）。返回 `{ orderNo, status }`。 |
| `POST /api/v1/payment/webhook/stripe` | 机器对机器接口，**不走 ApiResponse**。`byte[]` 收原始 body、限 1 MB；`Webhook.constructEvent` 验签；只处理 `payment_intent.succeeded`（→ `settlePaid`）与 `payment_intent.payment_failed`（→ 条件置 FAILED），其余静默 200。验签失败 / 缺签名头 / 超长回 400，处理异常回 500 让 Stripe 重试。异常在本控制器内消化，绝不漏给全局异常处理器（否则被包装成 200，Stripe 视为已送达）。`metadata.product != "lane"` 的事件跳过（同一 Stripe 账号多业务共用）。 |

### 6.4 入账与履约 `PaymentService.settlePaid(orderNo, intentId, amountMinor, currency)`

1. 查单，无则记日志返回（webhook 仍回 2xx）。
2. `payment_trade_no` 若已有且与 intentId 不一致 → 记 warn 返回。
3. 金额与币种逐项与订单相等（整数直接比较，币种不区分大小写），不等 → 记 error 返回，不入账。
4. `TransactionTemplate` 内：
   - 条件 UPDATE：`WHERE order_no = ? AND status IN (PENDING, FAILED, CANCELLED, EXPIRED)` → `SET status = PAID, paid_at = now, payment_provider = 'stripe', payment_trade_no = ?`。**IN 里含 CANCELLED / EXPIRED 是设计决定**：钱已收必须履约，取消/过期与到账的竞态下订单照常成立。
   - 影响 0 行 → 已处理过（重放），返回。
   - 影响 1 行 → INSERT `subscription`（`user_id`、快照五列从订单来，`assignment_no` 用 `AssignmentNo.generate()` 撞唯一键重试，起止为空，remark 写订单号），再 UPDATE 订单 `subscription_id`。
5. 事务提交后（`TransactionSynchronization.afterCommit`）异步推飞书卡片，尽力而为，异常只记日志。

幂等完全靠条件 UPDATE，不建事件去重表。verify 与 webhook 复用同一个 `settlePaid`。

### 6.5 飞书通知

新增 `OrderNotifyService`，复用现有 `NotifyProperties`（`notify.feishu.*`）与 `FeishuBotClient.sendCard`，模板 `GREEN`，标题「新订单已支付，待开通」，字段：买家邮箱、套餐、agent 类型、时长、金额币种、订单号、订阅分配号。`webhook-url` 未配置则静默不推。

### 6.6 Stripe 封装与配置

- `pom.xml` 加 `com.stripe:stripe-java:33.4.2`。
- `client/StripeGateway`：SDK **唯一封装点**。`StripeClient` volatile 懒初始化 + 双检锁，配置为空则 `PAYMENT_NOT_CONFIGURED`。`createPaymentIntent(orderNo, amountMinor, currency, subject, paymentMethodTypes)`：`setCurrency(currency.name().toLowerCase())`、`putMetadata("orderId", orderNo)`、`putMetadata("product", productCode)`、幂等键 `pi-<orderNo>`、含 `wechat_pay` 时必带 `client = WEB`、`statement_descriptor_suffix`。另有 `retrievePaymentIntent`、`cancelPaymentIntent`、`constructEvent`。
- `config/PaymentProperties`（`payment.stripe.*`）：

| key | 默认 | 说明 |
|---|---|---|
| `secret-key` | — | 敏感 |
| `webhook-secret` | — | 敏感 |
| `publishable-key` | — | 下发前端 |
| `supported-types` | `card,alipay,wxpay` | 我方命名；`wxpay → wechat_pay`、`alipay → alipay`、`card → card`，映射表与前端逐字一致；空则回退 `card` |
| `statement-descriptor-suffix` | `LANE` | 卡账单显示 `MINTPOP* LANE` |
| `product-code` | `lane` | 写入 metadata，webhook 认领本业务事件 |

`isConfigured()` = `secret-key` 与 `publishable-key` 均非空。`config/OrderProperties`（`order.expire-minutes`，默认 30）。

- 密钥只在 jar 外 `config/application.yml`；`apps/server/config/application.example.yml` 增 `payment.stripe` 与 `order` 段（占位文字）。仓库任何文件不得出现 `sk_live` / `sk_test`。
- `SecurityConfig`：`POST /api/v1/payment/webhook/stripe` 加 `permitAll`，放在 `/api/**` 之前。

- **我的订阅 `SubscriptionsView`**：数据来自 `/api/me`。每条一张卡：套餐名、agent 类型、分配号（等宽）；三档状态用 `.pill`：**待开通**（琥珀，`startsAt === null`，副文案「管理员开通后这里会显示起止时间」）、**在期**（绿，显示起止）、**已过期**（灰）。空态：「还没有订阅」+ 去购买套餐按钮。
- **购买套餐 `PlansView`**：`GET /api/plans`，按 agent 类型分 tab（复用 `ViewTabs`，只列有套餐的类型），卡片展示名称、`N 天`、`价格 币种`，按钮「购买」→ `POST /api/orders` → `router.push('/pay/' + orderNo)`。`checkout-info` 的 `methods` 为空时按钮禁用并提示「支付暂未开放」。非 ACTIVE 用户点购买收到 `USER_NOT_ACTIVE` 的 msg toast。
- **我的订单 `OrdersView`**：列表（订单号等宽、套餐、金额、状态 pill、时间）；PENDING / FAILED 行有「去支付」（`/pay/:orderNo`）与「取消」（`ConfirmDialog` 二次确认）；PAID 行显示「已开通订阅 · 分配号」或「待开通」。
- **支付页 `PayView`**：复制 shop 的 `payment.ts`（`STRIPE_SUB_METHODS`、`STRIPE_PM_TYPE`、`buildPayOptions`、`isPaidStatus`）与 `stripe.ts`（`getStripe` 懒加载、微信二维码 `handleActions:false`、支付宝桌面二维码 / 移动端整页跳转、银行卡 Payment Element deferred 模式只渲染 card、`redirect: 'if_required'`）。加载时并行取 `checkout-info` 与 `intent`；订单倒计时归零主动 verify；确认前再 verify 一次；发起后每 2 秒 verify，命中 PAID 跳结果页，EXPIRED / CANCELLED 为终态。`return_url = ${location.origin}/payment/result?order_no=`。**成功口径只认 `PAID`**（lane 无 COMPLETED）。
- **结果页 `PaymentResultView`**：进页先 `router.replace` 清掉 Stripe 追加的 query；最多 15 次 × 2 秒 verify；超时转「结果待确认」不报失败；终态守卫防慢响应翻转；成功态文案「已支付，管理员开通后可在「我的订阅」查看」，按钮去我的订阅。
- **外链**：Stripe.js（`js.stripe.com`）由 Stripe 禁止自托管，属可达性规范「无法自托管的第三方服务」——只在支付页按需异步加载，加载失败给出「支付组件加载失败，请检查网络后重试」而不是白屏；其它页面零外链。

## 八、管理端改动（`apps/admin`）

- `types.ts`：`AdminSubscriptionResponse.startsAt / endsAt: string | null`，`MeSubscription` 同步。
- `UserDetailView`：订阅列表对待开通行显示琥珀 `.pill`「待开通」，起止列显示「—」；「签发凭证」按钮待开通时禁用，title「先填写起期开通后再签发」。编辑表单：`subscriptionToForm` 对空起期给 `null`，表单起期留空由管理员填，提交校验仍必填；`predictedEndsAt` 照常按快照时长预览。
- `subscriptionForm.ts` 与相应 spec 同步。
- 服务端 `AdminSubscriptionResponse` 起止改可空（record 字段本就允许 null，只改文档注释与前端类型）。

## 九、错误处理与安全

- 业务失败一律 `ApiResponse` + 业务码，前端只看 `code`；401 / 403 仍走原生状态码由 http 层分流。
- 订单接口一律「会话 userId + orderNo」查单，越权访问表现为 `ORDER_NOT_FOUND`。
- 入账校验以订单的 `amount_minor` 与 `plan_currency` 为准，与 Stripe 回传逐项相等才入账。
- webhook 用官方 SDK 验签，禁止自行解析 JSON 后校验；body 限 1 MB。
- 前端只持有 publishable key 与 client_secret，不持有任何 secret。
- 密钥只在 jar 外配置文件；上线前 `grep -rn 'sk_live\|sk_test'` 全仓零命中。

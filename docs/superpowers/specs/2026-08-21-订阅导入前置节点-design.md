# 订阅链接导入前置节点 + 节点分组设计

日期：2026-08-21
状态：已与维护者确认设计，待实现

## 背景与问题

当前节点池（`proxy_node`）只有「逐个手填」一条录入路：管理端 `NodeFormModal` 表单一次建一个节点。而运维实际拿到的往往是机场订阅链接（如 `https://.../client/dy?token=...`），一份订阅里有几十上百个节点，逐个手抄不现实。

对示例订阅的实测结论（决定了解析方案）：

- 带 mihomo/Clash UA 请求时，订阅端返回**完整 Clash YAML 配置**，`proxies:` 列表里每个元素就是现成的 mihomo 节点参数 map（name/type/server/port/password/...），与后端出站的 `ProxyNodeDto.toMihomoNode()` 天然同构；带普通 UA 则返回 base64 的节点 URI 列表（信息更少、要逐协议写解析器）。
- 示例订阅 84 个节点为 83 个 anytls + 1 个 vless，**全部不在现有 `NodeProtocol` 枚举（TROJAN/SOCKS5/VMESS）内**。
- 订阅里混有「剩余流量：xx GB」「距离下次重置剩余：xx 天」「套餐到期：xx」这类**信息假节点**（有合法 server/port，但不是真节点）。

## 已确认的决策

1. **分组保存订阅链接，支持重新拉取**：分组表存订阅 URL（含 token，属凭据，加密落库），以后可对分组「重新拉取」增量导入或更新参数。
2. **协议走通用透传**：不逐个扩协议枚举；新增 `MIHOMO` 通用协议，把订阅节点的整份 mihomo 参数 map 作为敏感配置整体加密存储，下发时透传。任何 mihomo 支持的协议都能导入，且永远不会漏加密某个密钥字段。
3. **导入的节点固定 `role=FRONT`**（前置/第一跳）。
4. 一期**只解析 Clash YAML 格式**的订阅输出（请求时带 mihomo UA，机场基本都返回该格式）；base64 URI 列表格式不做，解析失败给明确业务错误码。

## 数据模型（Flyway `V2__node_group.sql`）

### 新表 `node_group`

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT PK AUTO_INCREMENT | 主键 |
| `name` | VARCHAR(64) NOT NULL，UNIQUE `uk_node_group_name` | 分组名，管理员起名 |
| `sub_url_cipher` | TEXT NOT NULL | 订阅链接的 AES-GCM 密文（链接含 token 属凭据，复用 `AesGcmCredentialCipher`，形态同 `secret_cipher`） |
| `remark` | VARCHAR(255) NULL | 备注 |
| `created_at` / `updated_at` | DATETIME | UTC，同现有表写法 |

表与全部字段带中文 COMMENT（遵循数据库注释规范）。

### `proxy_node` 加三列

- `group_id` BIGINT NULL，FK → `node_group(id)`：所属分组；NULL 表示手工节点、不属于任何分组。
- `source_name` VARCHAR(128) NULL：订阅里的原始节点名。重新拉取时以「同组内 `source_name` 相同」为同一节点的判定，命中则原地更新参数，未命中视为新节点。手工节点为 NULL。
- `source_type` VARCHAR(32) NULL：订阅节点的真实 mihomo type（如 `anytls`、`vless`），明文落列仅供列表展示（协议列显示「MIHOMO」没有信息量）；与 `server_addr`/`port` 同理，下发不读它。手工节点为 NULL。

### 协议枚举

`NodeProtocol` 新增成员 **`MIHOMO`**（`secretKeys` 概念对它不适用——它的敏感配置是整份 map，见下）。DB `protocol` 列 COMMENT 同步补充。前端 `types.ts` 的 `NODE_PROTOCOL` 逐字镜像。

### MIHOMO 节点的存储形态

- `secret_cipher`：整份 mihomo 节点参数 map（订阅原样，**去掉 `name` 键**）的 JSON 加密密文。`type`/`server`/`port` 也在其中。
- `extra_config`：留空（`NULL`）。
- `server_addr` / `port`：从 map 中提取一份落列，仅供管理端列表展示与检索，下发不读它们。
- `name`：默认取订阅节点名；撞 `uk_proxy_node_name` 全局唯一约束时自动加后缀 `(2)`、`(3)`…（订阅名可能超 64 或含 emoji，超长截断后再拼后缀）。

### 下发侧适配

`ProxyNodeDto.toMihomoNode()` 增加分支：`protocol == MIHOMO` 时直接返回解密后的 map 副本（其内自带 type/server/port），不再从列拼装；其余协议行为不变。name 与 dialer-proxy 仍由客户端覆盖，行为一致。

## 后端

### 订阅拉取与解析

命名统一用 **`Sub` 前缀**（如 `SubFetchClient`、`SubYamlParser`），**不叫 `subscription`**——仓内 `subscription` 表/包指售卖订阅，撞名会误导。拉取放 `ai.mintpop.lane.client` 包（外呼 HTTP 客户端归 client 包），解析放 `ai.mintpop.lane.parser` 包。

- HTTP：Spring 自带 `RestClient`，UA 设为 mihomo 风格（如 `clash.meta`），超时钉死（连接/读各 10s 量级）。`RestClient` 作为 bean 在组装层创建注入（遵循 DI 规范），测试可注入 mock。
- 解析：snakeyaml（Spring Boot 自带传递依赖）`SafeConstructor` 解析 YAML，只取顶层 `proxies:` 列表，忽略其余段（proxy-groups/rules/dns 等）。每个元素校验必须含 `name`/`type`/`server`/`port`，缺失的条目跳过。
- 信息假节点识别：按名称启发式（含「流量」「重置」「到期」「官网」「过期」等关键词）打 `suspectedInfo: true` 标记，**只影响前端默认勾选状态，不做硬过滤**——所有条目都展示，管理员自己决定。

### 接口（均挂 `/api/admin`，ROLE_ADMIN，统一 `ApiResponse<T>`）

新 Controller：`AdminNodeGroupController`；业务在 `AdminNodeGroupService`。

| 接口 | 行为 |
|---|---|
| `POST /node-groups/preview` | 入参 `{subUrl}`。拉取解析，返回节点清单：`[{sourceName, type, serverAddr, port, suspectedInfo}]`，**不含敏感参数、不落库** |
| `POST /node-groups` | 入参 `{name, subUrl, selectedNames[]}`。后端**重新拉取一次**订阅、按 `selectedNames` 过滤后建分组 + 入库节点（敏感参数不经前端往返）。分组重名报错 |
| `GET /node-groups` | 分组列表：`[{id, name, subUrlMasked, nodeCount, createdAt, updatedAt}]`。`subUrlMasked` 只回显打码后的链接（如仅保留 host + token 前 4 位），完整链接不出库 |
| `PUT /node-groups/{id}` | 改名（及备注）；重名报错。不支持改订阅链接（换链接 = 建新分组） |
| `POST /node-groups/{id}/refresh-preview` | 用库里存的链接重拉，返回同 preview 的清单，每条附 `existed: true/false`（同组 `source_name` 是否已入池） |
| `POST /node-groups/{id}/import` | 入参 `{selectedNames[]}`。重拉后按勾选导入：`source_name` 已存在 → 原地更新参数（secret_cipher/server_addr/port，name/status/remark 不动）；不存在 → 新建入组 |
| `DELETE /node-groups/{id}` | 删除分组并**连带删除组内全部节点**；组内任一节点被 `app_user` 绑定则整体拒绝（不做部分删除） |

现有 `GET /api/admin/nodes` 的出参 `AdminNodeResponse` 增加 `groupId`/`groupName`（NULL 即手工节点），供列表展示与筛选。

### 业务规则与错误码（`BizCodeEnum` 41 段续编）

- `NODE_GROUP_NOT_FOUND(410009, "分组不存在")`
- `NODE_GROUP_NAME_DUPLICATED(410010, "分组名已存在")`
- `SUB_FETCH_FAILED(410011, "订阅拉取失败")`（网络错误/非 2xx/超时）
- `SUB_PARSE_FAILED(410012, "订阅解析失败")`（非 YAML/无 proxies/为空）
- `NODE_GROUP_IN_USE(410013, "分组内有节点被用户引用，无法删除")`
- `SELECTED_NODE_MISSING(410014, "勾选的节点在订阅中不存在")`（preview 与 confirm 之间订阅内容变了）

其余沿用现有规则：MIHOMO 节点同样受「被引用禁止删」（410003）约束；`AdminNodeServiceImpl` 现有「敏感键不得混入 extraConfig」校验对 MIHOMO 不适用（其 extra_config 恒空），手动新建/编辑表单**不提供 MIHOMO 选项**（该协议只能经导入产生）。

## 管理端（apps/admin）

### NodesView「第一跳」tab

- 顶部加**分组筛选条**：`全部 / 未分组 / <各分组名>` 的 chips；LAND tab 不显示（分组只属于 FRONT）。
- 列表加「分组」列。
- 工具栏加 **「从订阅导入」** 按钮。
- 分组 chip 带操作菜单：**改名**、**重新拉取**、**删除**（删除需确认弹窗，文案明示会连带删除组内节点）。

### 导入弹窗（新组件 `SubImportModal.vue`）

三步式，复用 `AdminModal`：

1. **贴链接**：输入订阅 URL → 调 `preview`。
2. **勾选节点**：表格展示 名称/协议/地址/端口，支持全选/反选；`suspectedInfo` 条目默认不勾并有视觉提示（如灰字 + 「疑似信息条目」标签）；重新拉取场景下 `existed` 条目标「已入池」且默认不勾（勾选表示更新其参数）。
3. **命名确认**：填分组名（重新拉取场景跳过此步）→ 调 `POST /node-groups` 或 `.../import` → 成功后刷新列表。

### 节点编辑弹窗适配

`NodeFormModal` 对 `protocol === "MIHOMO"` 的节点：协议/地址/端口/敏感配置/透传键全部禁用（参数更新走重新拉取），仅名称/状态/备注可改。协议下拉不出现 MIHOMO 选项（不能手工新建）。

### 类型镜像（`api/types.ts` + `api/admin.ts`）

- `NODE_PROTOCOL` 加 `MIHOMO`（现无 `NODE_PROTOCOL_LABELS`，界面直接显示枚举名；MIHOMO 节点列表中的协议列显示订阅里的真实 type 更有用，故 `AdminNodeResponse`/`SubPreviewNode` 均带 `sourceType` 字段，如 `anytls`）。
- 新增 `NodeGroupResponse`、`SubPreviewNode`、分组相关请求类型；`AdminNodeResponse` 镜像加 `groupId`/`groupName`。
- `api/admin.ts` 加分组五个接口的薄封装。

## 测试

- **解析器单测**：用脱敏后的真实订阅 YAML 作 fixture——正常解析出条目、忽略 proxy-groups、缺 name/server 的条目跳过、信息假节点标记命中、非 YAML 输入抛解析错误。
- **Service 单测**：创建分组（重名拒绝、selectedNames 过滤、撞节点名加后缀、超长截断）、重新拉取（source_name 命中更新/未命中新建）、删除分组（组内节点被引用整体拒绝、正常连带删除）、订阅链接加密落库与打码回显。
- **下发侧**：`toMihomoNode()` 对 MIHOMO 分支——输出即解密 map、不混入列上的 server/port、不含 name。
- **前端 Vitest**：SubImportModal 三步流转、默认勾选逻辑（suspectedInfo/existed 不勾）、分组筛选条过滤行为、MIHOMO 节点编辑弹窗字段禁用。

## 不做的事（YAGNI）

- 不做 base64 URI 列表格式解析（一期只吃 Clash YAML；遇到不返回 YAML 的机场再说）。
- 不做定时自动刷新订阅——刷新永远是管理员手动触发。
- 不做「按协议逐个建模」——MIHOMO 透传已覆盖；TROJAN/SOCKS5/VMESS 手工路径维持原样。
- 不做订阅流量/到期信息（`subscription-userinfo` 响应头）的展示。
- 不做分组换绑订阅链接、节点跨分组移动。

## 风险提示（不在本次改动范围）

- anytls 等新协议需要桌面端 mihomo 内核 ≥ 1.19.3 才能识别；桌面端在独立仓库 `mintpop-lane-desktop`，上线前需确认其内核版本，否则下发了客户端也起不来。

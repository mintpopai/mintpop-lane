# 套餐商品化：套餐图上传与文案（参考 mintpop-shop 的商品）

> 日期：2026-09-16 · 状态：已确认，待实施
> 涉及：`apps/server`、`apps/admin`、`apps/console`（官网不动）

## 一、背景

`plan` 表现在只有 `name / agent_type / duration_days / price / currency / enabled / remark` 七列，既没有面向用户的文案，也没有图。控制台的购买页（`apps/console/src/views/PlansView.vue`）因此只能渲染「名称 + N 天 + 价格 + 购买按钮」一行式卡片，用户在掏钱前看不到这个套餐到底包含什么。

姊妹项目 **mintpop-shop** 的商品已经具备这套能力：管理端能传图（Cloudflare R2）、写短描述、写富文本详情，商城前端有商品卡与商品详情页。本次把其中的**图片上传**与**说明文案**两件事移植到 lane 的套餐上。

官网（`apps/website`）的定价区是写死在 `src/content/copy.ts` 里的静态文案、不走 API，**本次不涉及官网**。

## 二、已确认的决策

1. **范围＝图片上传 + 短描述 + 富文本详情**，其余商品字段（分组、主题色、角标、库存、展示销量、跳转链接、中英双语）**一概不搬**——lane 的套餐不是电商 SKU，管理端与控制台都是纯中文、无 i18n。
2. **分两批交付**：第一批只做 R2 上传基建 + `image_url` + `description`；第二批做 `detail` 富文本。R2 是 lane 从零接的新基建，第一次接要验的东西（凭据、自定义域、R2 特有的签名坑、缓存头）与富文本那一串（编辑器、两道净化、展示位）混在一个改动里出了问题不好定位。分批不少任何功能，只改交付顺序。
3. **富文本详情在控制台走弹窗，不另开路由页**。控制台是登录后的内部页面，套餐详情有没有独立 URL 没人在乎；弹窗还能让购买路径一步不变。
4. **R2 新开桶**，不复用 shop 的 `mintpop-shop-assets`：桶名 `mintpop-lane-assets`，自定义域 `assets.lane.mintpop.ai`，保持 `<组件>.lane.mintpop.ai` 的域名结构。
5. **存储整段可选**：`storage.r2` 不配时上传接口报「图片存储未配置」，手填图片地址那条路照常可用，其它功能完全不受影响。本地开发因此不必配 R2。

## 三、非目标

- 不做图片的删除与垃圾回收（见「九、已知取舍」）。
- 不做图片裁剪、压缩、缩略图生成——原图直传，前端用 CSS 控制显示尺寸。
- 不做套餐的中英双语文案。
- 不改官网、不改桌面端、不改订单与支付链路。
- 不把上传能力开放给普通用户（只有 `/api/admin/**`）。

## 四、总体架构

```
管理端浏览器 ──┬─ POST /api/admin/uploads/images (multipart) ──▶ server ──▶ Cloudflare R2
               │                                                  ↑         (mintpop-lane-assets)
               │                                       返回公开 URL │
               └─ PUT  /api/admin/plans/{id} (JSON, 含 imageUrl) ─▶ server ──▶ MySQL plan 表

控制台浏览器 ──── GET /api/plans ──▶ server ──▶ MySQL
               └─ <img src="https://assets.lane.mintpop.ai/plans/…"> ──▶ Cloudflare 边缘
```

图片本体**不经过服务端分发**：服务端只在上传时写一次 R2，之后浏览器直接从 `assets.lane.mintpop.ai` 取图，走 Cloudflare 边缘缓存（全球可达，符合 `global-reachability.md`）。

## 五、数据模型

三列全部可空，存量套餐无需补数据，控制台按有无渲染。

### 5.1 第一批 `V18__plan_media.sql`

```sql
ALTER TABLE plan
    ADD COLUMN description VARCHAR(255) NULL COMMENT '套餐短描述，控制台购买卡片的副标题，可空' AFTER currency,
    ADD COLUMN image_url   VARCHAR(512) NULL COMMENT '套餐图公开 URL（R2 自定义域下的地址），可空' AFTER description;
```

### 5.2 第二批 `V19__plan_detail.sql`

```sql
ALTER TABLE plan
    ADD COLUMN detail MEDIUMTEXT NULL COMMENT '套餐详情富文本，入库前已按白名单净化的 HTML，可空' AFTER image_url;
```

### 5.3 空值语义

- `description` / `image_url` 与既有的 `remark` 一致：前端提交前 `trim()`，服务端按 `@Size` 校验后原样入库。
- `detail` 例外：经 `HtmlSanitizer` 净化，净化后不剩内容时归 `null`，库里不混存 `<p></p>` 这类空壳。

## 六、服务端：存储基建（第一批）

全部照搬 mintpop-shop 的同名实现，包名改 `ai.mintpop.lane`，**枚举去掉 shop 的 `Enum` 后缀**以随 lane 现有惯例（`AgentType`、`Currency`）。

| 新增类 | 职责与要点 |
|---|---|
| `config/StorageProperties` | `@ConfigurationProperties("storage.r2")`，五项：`account-id` / `access-key-id` / `secret-access-key` / `bucket` / `public-base-url`；`isConfigured()` 判五项都非空白；`endpoint()` 拼 `https://<accountId>.r2.cloudflarestorage.com` |
| `config/StorageConfiguredCondition` | 用 `Binder` 绑 `storage.r2` 后调 `isConfigured()`。**不用 `@ConditionalOnProperty`**——YAML 里 `access-key-id:` 留空也算「属性存在」，会走到 `AwsBasicCredentials.create("","")` 抛异常让整个应用起不来，与「整段可选、不配则优雅降级」相悖 |
| `config/StorageConfig` | `@Conditional(StorageConfiguredCondition.class)` 挂在**类**上（`@ConditionalOnBean` 只在自动配置里可靠）。装配 `S3Client` + `R2StorageClient` 两个 bean |
| `client/R2StorageClient` | 只管「写对象 + 拼公开 URL」，不懂业务；SDK 异常原样上抛由服务层翻译。`Cache-Control: public, max-age=31536000, immutable`（对象键含 UUID，永不覆盖） |
| `enumeration/ImageType` | `JPEG/PNG/WEBP/GIF`，各带 `mimeType` + `extension`。成员名 SCREAMING_SNAKE_CASE |
| `util/ImageTypeDetector` | 按文件头魔数判型，只看前 12 字节（WebP 的 `WEBP` 标记在 8–11 字节）。**这是把 SVG/HTML 以图片名义写进公开桶的口子堵死的地方**——不信浏览器传的 Content-Type，也不信文件扩展名 |
| `service/ImageUploadService` | 校验（存储已配置 → 非空 → ≤5 MB → 魔数判型）→ 生成对象键 → 写 R2 → 返回 URL。构造器注入 `Optional<R2StorageClient>` 与 `Clock`（测试注固定时钟断言键里的年月） |
| `controller/admin/AdminUploadController` | `POST /api/admin/uploads/images`，入参 `@RequestParam("file") MultipartFile`。`/api/admin/**` 已由 `SecurityConfig` 统一要求 `ROLE_ADMIN`，本类不再自行鉴权 |
| `response/ImageUploadResponse` | `record ImageUploadResponse(String url)` |

**对象键**：`plans/yyyy/MM/<uuid>.<ext>`（UTC 年月分目录，便于在 R2 控制台翻看）。

**依赖注入**：全部用显式构造器注入，与 lane 现有的 `PlanController` / `AdminPlanServiceImpl` 写法一致，不引 Lombok 的 `@RequiredArgsConstructor`。测试可以直接构造传假实现，不需要打模块补丁。

### 6.2 依赖与配置

`pom.xml`：

```xml
<!-- properties -->
<aws-sdk.version>2.46.7</aws-sdk.version>
<jsoup.version>1.21.1</jsoup.version>   <!-- 第二批才加 -->

<!-- Cloudflare R2 对象存储（S3 兼容）。只用同步客户端，排除给异步客户端用的 netty -->
<dependency>
  <groupId>software.amazon.awssdk</groupId>
  <artifactId>s3</artifactId>
  <exclusions>
    <exclusion>
      <groupId>software.amazon.awssdk</groupId>
      <artifactId>netty-nio-client</artifactId>
    </exclusion>
  </exclusions>
</dependency>
```

`S3Client` 的装配按 Cloudflare 官方 Java SDK 示例：`region` 固定 `auto`（SDK 必填、R2 不用）、`pathStyleAccessEnabled(true)`、**`chunkedEncodingEnabled(false)`**（SDK 对 `putObject` 默认 chunked transfer，R2 会回 **HTTP 403 签名不匹配**）、`requestChecksumCalculation`/`responseChecksumValidation` 都设 `WHEN_REQUIRED`（SDK 2.30 起默认给每个请求加 CRC32，第三方 S3 兼容存储按需即可）。

`application.yml`（同步写进 `application.example.yml`，带中文注释说明整段可选）：

```yaml
spring:
  servlet:
    multipart:
      max-file-size: 5MB
      max-request-size: 6MB

# 可选：不配则图片上传接口报「图片存储未配置」，手填图片地址照常可用
storage:
  r2:
    account-id: ""
    access-key-id: ""
    secret-access-key: ""
    bucket: mintpop-lane-assets
    public-base-url: https://assets.lane.mintpop.ai
```

凭据进宿主机 jar 外的 `application.yml`（已 gitignore），不入库、不进镜像。

## 七、服务端：套餐字段（第一批 + 第二批）

| 类 | 第一批加 | 第二批加 |
|---|---|---|
| `entity/Plan` | `description`、`imageUrl` | `detail` |
| `request/PlanSaveRequest` | `@Size(max=255) description`；`imageUrl` 用 `@Size(max=512)` + `@Pattern(regexp = "^https://.+")`（`@Pattern` 对 `null` 天然放行，可空语义不受影响） | `detail`（无长度上限，由 `MEDIUMTEXT` 兜底） |
| `response/PlanResponse` | 同上两项 | `detail` |
| `response/UserPlanResponse` | 同上两项 | `detail` |
| `AdminPlanServiceImpl` | `apply()` / `toResponse()` 同步 | 同步，且 `detail` 过 `HtmlSanitizer` |

**`UserPlanResponse` 也要加**：控制台卡片就靠它。`detail` 会随 `GET /api/plans` 全量下发（列表接口一次带回所有上架套餐的富文本）——套餐总共个位数，这点体量不值得为它拆一个单独的详情接口；哪天套餐多到列表明显变慢，再把 `detail` 摘出去走 `GET /api/plans/{id}`。该 record 现在刻意只暴露「购买决策要看的字段」，图与文案正好在这个语义之内；管理员备注与上架状态仍然不出现。

第二批新增 `util/HtmlSanitizer`（`@Component`，jsoup `Safelist.relaxed()` 额外放行 `a` 的 `target`/`rel`，`prettyPrint(false)`）。**净化收口在入库前这一处**——库里只存干净 HTML，换任何客户端都绕不过去。

## 八、前端

### 8.1 管理端第一批：不动布局，只加两个字段

这一批的目标是打通 R2 链路，顺带做布局重构会让出问题时分不清是谁的锅。`PlanFormModal.vue` 仍是现在的单列窄弹窗，在「备注」之前插入：

- **短描述**：`textarea` + 字数计数（255 上限，超了标红），配一句 `field-note`：「控制台购买卡片上名称下面那行小字」。
- **套餐图**：URL 输入框 + `ImageUploadButton` 并排，下方预览位。地址取不到图时预览位给一句人话而不是碎图标（`@error` 兜住），`watch` 到地址变化就清掉上一次的失败态，别把上一张的失败留在新地址上。

新增 `components/ImageUploadButton.vue`（照搬 shop）：只管「选文件 → 上传 → 抛 URL」，5 MB 本地预检（与后端 `MAX_BYTES`、`spring.servlet.multipart.max-file-size` 三处一致），失败走全局 toast，拿到 URL 之后怎么用由父组件决定。两个细节照抄：`<input type=file>` 的 `el.value = ''` 要立刻清（同一个文件再选一次浏览器才会再触发 `change`）；它要带 `tabindex="-1"`——`AdminModal` 的 `FOCUSABLE` 选择器会把 `display:none` 的它也算进 Tab 环。

`utils/planForm.ts` 扩 `description` / `imageUrl` 与对应校验（长度、URL 必须 `https://`）。

### 8.2 管理端 `api/http.ts`：两处必改

现在的 `createHttpClient` 会直接挡住上传：

1. **无条件写死了 `Content-Type: application/json`**。body 是 `FormData` 时必须**不写**这个头，让浏览器自己带 `boundary`，否则后端解析不出文件。改成 `...(init.body instanceof FormData ? {} : { "Content-Type": "application/json" })`。
2. **加 413 分支**：反代（容器内 nginx / 宿主 OpenResty）拦下超大请求体时请求到不了 Spring，没有业务码，现在只会落进 `服务端返回异常状态：413`。给一句「文件太大，超出服务器允许的上传上限」。

### 8.3 管理端第二批：改两栏 + 富文本

`AdminModal` 加 `flush` prop（内容区不留内边距，供内部自己分栏且底色铺到弹窗边缘；`wide` 已有，够当 shop 的 `size="lg"` 用）。`PlanFormModal` 重排为左右两栏：

- **左「文案」栏**：套餐名 → 短描述 → 富文本详情（撑满剩余高度）
- **右「参数」栏**：Agent 类型 → 时长 → 价格 + 币种 → 状态 → 套餐图 + 预览 → 备注

新增 `components/RichTextEditor.vue`（TipTap，对外就是一个 `v-model` 绑 HTML 字符串的输入框）。依赖按 lane 惯例**钉精确版本**（`apps/admin/package.json` 现有依赖都无 `^`）：`@tiptap/vue-3`、`@tiptap/starter-kit`、`@tiptap/extension-image`、`@tiptap/pm` 均 `3.30.2`。搬运时照抄 shop 的两处关键处理：

- 空文档时 TipTap 给的是 `<p></p>` 这类空壳，对外一律归一成空串；
- 外部回填（打开编辑弹窗）时，**内容与当前一致就跳过 `setContent`**——重建文档会把光标打回开头，正在打字的人会当场跳字。

详情里插图复用同一个 `ImageUploadButton`，不开 base64 内联。

### 8.4 控制台

**第一批**：`PlansView` 的卡片左侧加缩略图（64×64 圆角容器，无图则不占位——`.plan-card` 本就是 flex），`.plan-text` 里名称下补一行描述（单行省略），原来的「N 天」降为第三行。样式改 `apps/console/src/styles/layout.css` 的 `.plan-card` 一段。

**第二批**：有 `detail` 的套餐，购买按钮旁多一个「详情」文字按钮，点开 `AdminModal wide` —— 大图 + 描述 + 富文本正文 + 一个购买按钮；没 `detail` 就不显示该按钮，购买路径一步不变。

富文本走 `v-html`，**渲染前再过一遍 DOMPurify**（console 新增依赖 `dompurify` `3.4.14`，精确版本）。后端入库时已按白名单净化过，这里是纵深防御：历史脏数据、或哪天多出别的写入口，都不至于直达 `v-html`。

## 九、部署与运维

### 9.1 Cloudflare R2

1. 新建桶 `mintpop-lane-assets`。
2. 绑定自定义域 `assets.lane.mintpop.ai`。
3. 建 R2 API Token（仅该桶的对象读写），把 Access Key ID / Secret 填进宿主机 `application.yml` 的 `storage.r2`。

⚠️ **TLS 提醒**：`assets.lane.mintpop.ai` 是 `mintpop.ai` 的**二级子域**，Universal SSL 的通配符只匹配一层、覆盖不到它，靠已开通的 **ACM + Total TLS** 兜底，而 Total TLS **只为橙云代理的 hostname 签证书**（R2 自定义域默认即代理）。上线后验一次：

```bash
curl -o /dev/null -w '%{http_code}\n' https://assets.lane.mintpop.ai/<任一已上传对象键>
```

排查该域名时**别信本机 `dig`**（clash TUN + fake-ip 会把所有查询返回 `198.18.x.x`），走 DoH：
`curl -s -H 'accept: application/dns-json' 'https://cloudflare-dns.com/dns-query?name=assets.lane.mintpop.ai&type=A'`。

### 9.2 nginx 上传体积（最容易漏的一处）

`client_max_body_size` 默认 **1 MB**，5 MB 的图会被 **413** 挡在 Spring 之前。两层都要放行：

- `apps/admin/nginx.conf` 的 `location /api/` 加 `client_max_body_size 6m;`；
- **宿主机 OpenResty 那层也得同样放行**——只改容器内这层没用。这条写进 README 的部署说明。

## 十一、已知取舍

1. **孤儿图片不回收**：换图或删套餐后，旧对象留在 R2 桶里没人清（mintpop-shop 同样如此）。套餐总共几个、图也就几十 KB，为它做引用计数与 GC 不值当。哪天真需要，写个按 `plans/` 前缀与库里 `image_url` 对账的一次性脚本即可。
2. **本地开发默认没有 R2**：不配 `storage.r2` 时上传按钮点了报「图片存储未配置」，手填图片地址那条路照常可用，其它功能完全不受影响。
3. **不做图片处理**：原图直传，没有裁剪、压缩与缩略图。上传 5 MB 的大图，控制台卡片上那个 64×64 的缩略位也会拉整张原图。真成问题时再上 Cloudflare Images 或 R2 前面挂 Image Resizing，本次不做。

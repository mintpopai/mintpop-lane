# 第一跳可观测性四期：三期终审留下的优先项

**日期**：2026-09-21
**前置**：三期（`2026-09-17-第一跳稳定性与可观测性-design.md` §8，计划 `2026-09-19-第一跳可观测性三期-链路上报.md`）已合入两仓本地 main（服务端 `01427b2`、桌面端 `d01f4da`），未推送、未发版。
**范围**：三期两仓终审点名的 8 项「下一期优先」，桌面端 4 项、服务端 4 项。**不含**三期分流为「可留后续」的其余 Minor（那些仍在三期终审报告里，本期不碰）。
**跨两个仓库**；两边之间只有一份接口——心跳上报契约 `LinkHeartbeatRequest`，**本期不改它**。改的是管理端查询契约（`LinkHealthResponse`）与三张表的运营商列。

## 一、目标与不做的事

三期把「第一跳健康状况」第一次变得可见，但终审在两边各留下几处「能跑、但会在某种真实情形下说错话」的地方：

- 桌面端：入口 IP 与窗口靠两处独立读取「恰好同序」对齐；断链后采样循环对空壳内核空转到手动重连；心跳循环 70 行接线零自动化覆盖；累加器换代时在途的一轮采样可能记进新累加器。
- 服务端：告警去重状态没有过期，用户在劣化中离线后再回来不再告警；运营商维度拿自由文本当键，同一 ASN 文案漂移会裂列并重复告警；5 个定时任务挤在单线程调度器上；反查缓存的 TTL 与容量写死。

本期只修这 8 处。**不做**：采样并发化（终审 Minor 7）、`link_alert_state` 行清理、多实例共享缓存、前端阈值下发。

## 二、桌面端（`mintpop-lane-desktop`）

### 2.1 入口主机名并进 `DomainWindow`

**现状**：`WindowAccumulator::new_at(Vec<String>, SystemTime)` 只收故障域名；心跳时 `entry_hosts(state)` 现读 `state.link` 取每组首节点的 `server`，再按下标与 `take_window` 的窗口对齐。`establish_link` 先换 sampler 后换 link，中间插入的心跳会把新配置的入口贴到旧窗口上；残窗上报还要在建链前单独快照一份 `pending_hosts`。

**设计**：

- 新增 `pub struct DomainSpec { pub failure_domain: String, pub entry_host: Option<String> }`（`sampler.rs`）。`WindowAccumulator::new` / `new_at` 改收 `Vec<DomainSpec>`；`DomainWindow` 增加字段 `pub entry_host: Option<String>`，由累加器在建窗时填入、`take_window` 原样带出。
- `establish_link` 用 `usable_front_groups(&link)` 构造 `Vec<DomainSpec>`，`entry_host` 取现有 `entry_ip::entry_host(group)`。
- `build_report_blocks(window_start, windows)` 去掉第三个参数，按 `window.entry_host` 解析；删除 `entry_hosts()` 与 `pending_hosts` 快照。
- `rotate_sampler(state, specs, now)` 签名随之改。
- 行为不变的部分：`resolve` 的过滤与超时、`from_window` 的可空性、契约 JSON。

**测试**（`sampler.rs` / `report.rs` 单测）：
- 两个具名域 + 一个空组（空组不进 `usable_front_groups`），第一个域窗口为空被过滤，断言第二个块解析的是第二个域的主机名（用 IP 字面量避免 DNS）。
- 残窗：建链换代后交出的旧窗口带的是**旧**配置的主机名。

### 2.2 DISCONNECT 后停采样

**现状**：心跳判定 DISCONNECT 只 `reset_kernel`（内核推回空壳）不清 `link`；`sampler_loop` 据 `link` 拼出节点名对空壳内核每 30 秒打一轮 404，持续到用户手动重连；`prepare_update_install` 把 `kernel` 置 None 后同样每轮误报「途中被重置」。

**设计**：

- `AppState` 加 `kernel_configured: AtomicBool`。置 true：`establish_link` 推完配置、进入采样前。置 false：`reset_kernel`、`clear_link_state`、`prepare_update_install`。
- 采样前置判定抽成纯函数 `fn sampling_targets(link: Option<&LinkConfig>, kernel_configured: bool) -> Vec<String>`：未配置或无可用组返回空，循环开头为空即跳过。**不用 `link_situation` 判**：`EGRESS_MISMATCH` 等处境下内核有配置、正该采样。
- 「采样途中内核已被重置」两处日志改成只在 `kernel_configured` 为 true 却拿到 `None` 时打（真正的途中重置），否则静默跳过。

**测试**：`sampling_targets` 三条——未配置返回空；已配置且有组返回正确节点名；已配置但全部组为空返回空。

### 2.3 心跳循环可测，并与采样循环一起搬到 `link/report.rs`

**现状**：`lib.rs` 1640 行，`heartbeat_loop` 里 `select!` + `Notify` + 抖动抑制 + `next_beat` 重排 + 多块发送遇断链中止约 70 行无自动化覆盖；`next_beat` 用 `tokio::time::Instant`、`ReportCadence` 用 `std::time::Instant`，`tokio::time::pause` 只能拨前者。

**设计**：

- 新建 `src-tauri/src/link/report.rs`，搬入 `ReportCadence`、`build_report_blocks`、`heartbeat_loop`、`sampler_loop`、五个节奏常量（`HEARTBEAT_INTERVAL`、`REPORT_EVERY_N_BEATS`、`IMMEDIATE_REPORT_MIN_INTERVAL`、`SAMPLE_INTERVAL`、`SAMPLE_SETTLE`）与 2.2 的 `sampling_targets`。`lib.rs` 只保留 `run()` 里的两处 `spawn`。
- 循环体拆成两层：
  ```rust
  pub(crate) enum HeartbeatPlan {
      SKIP,                                            // 被抖动抑制压下，不打心跳、不动周期
      PLAIN,                                           // 打不带 body 的心跳
      WITH_BLOCKS { window_start: SystemTime, windows: Vec<DomainWindow> },
  }
  pub(crate) fn plan_heartbeat(
      state: &AppState, cadence: &mut ReportCadence, woken_by_jump: bool, now: tokio::time::Instant,
  ) -> HeartbeatPlan
  ```
  `plan_heartbeat` 负责抖动抑制、拍数计数、`take_window`，**不碰网络、不碰 `session_token`**；循环负责 `select!`、取 token、机器码检查、按计划发请求、逐响应裁决。
- `ReportCadence` 与 `next_beat` 统一用 `tokio::time::Instant`。
- `sampler_loop` 同样拆出纯逻辑：`sampling_targets`（2.2）与 2.4 的 `record_for`。

**测试**：
- 现有 `lib.rs` 里 8 条心跳/采样测试迁到 `report.rs`，改调 `plan_heartbeat`。
- 新增：跃变唤醒但在最小间隔内 → `SKIP` 且 `cadence` 不变；被唤醒且允许 → `WITH_BLOCKS` 且周期计数归零；第 5 拍 → `WITH_BLOCKS`；前 4 拍 → `PLAIN`；`ReportCadence` 用 `tokio::time::pause()` + `advance` 推时间。
- `select!`/`Notify` 接线仍无单测，报告如实标注；它剩下的逻辑是「等哪个先到」一行。

### 2.4 累加器世代号

**现状**：`sampler_loop` 一轮采样跨几十秒；`rotate_sampler` 在此期间换代后，本轮读到的旧内核快照会 `record` 进新累加器（终审 Minor「跨世代错归」）。

**设计**：

- `WindowAccumulator` 增加 `generation: u64`，`pub fn generation(&self) -> u64`。`new_at` 从 0 起；`rotate_sampler` 构造新累加器时传入 `old.generation() + 1`（提供 `new_at_generation(specs, start, generation)`）；`clear_link_state` 同样递增（构造空累加器时带 `old + 1`）。
- `record` 改为 `pub fn record_for(&mut self, generation: u64, statuses: &HashMap<String, ProxyStatus>) -> RecordOutcome`，`pub enum RecordOutcome { STALE, RECORDED { jumped: bool } }`。世代不匹配整轮丢弃、不记、不唤醒。
- `sampler_loop` 每轮开头读 `generation()`，`record_for` 时带上。

**测试**：换代后带旧世代号 → `STALE` 且窗口与基线不变；带新世代号照常记。

## 三、服务端（`mintpop-lane`）

### 3.1 运营商维度改 ASN 做键，名字只做展示

**现状**：`link_report.isp`（可空）、`link_report_daily.isp`、`link_alert_state.isp`（非空进唯一键）都存 ipwho.is 的自由文本 `connection.isp`；`source_asn` 只在 `link_report` 上，不参与任何键与 GROUP BY。同一 ASN 不同文案（如 "China Telecom" / "CHINANET-BACKBONE"）会在矩阵裂成两列、告警各推一次。

**决定**（用户已选）：**键用 ASN，名字只做展示。**

**迁移**：V22/V23 从未在任何环境执行过（三期 main 未推送、未部署），**原地改**、不叠 ALTER。⚠️ **对已有本地库的后果**（终审补充）：任何在三期期间起过服务端的开发机，其 MySQL 的 `flyway_schema_history` 记着旧版 V22/V23 的 checksum，合入四期后启动会在 Flyway validate 上直接失败（`Migration checksum mismatch`）。处置：**`DROP DATABASE` 重建**（让 V22/V23/V24 从头执行）。**不要只跑 `flyway repair`**——它只把 `flyway_schema_history` 的 checksum 对齐，不会重新执行迁移，本地库的列结构仍是旧的，启动后第一条碰 `asn` 列的 SQL 就会报 `Unknown column`。这是原地改的代价，只发生在本地开发库上。
- `link_report`：删除 `isp` 列；`source_asn` 保持可空（NULL = 反查失败）。
- `link_report_daily`：`isp VARCHAR(64)` → `asn VARCHAR(32) NOT NULL DEFAULT ''`（空串 = 反查失败，进唯一键的既定编码），唯一键 `(user_id, failure_domain, asn, stat_date)`。
- `link_alert_state`：同上，唯一键 `(user_id, failure_domain, asn)`；故障域级告警行 `asn` 存空串（沿用原来 isp 的约定）。
- 新增 `V24__asn_org.sql`：
  ```sql
  CREATE TABLE asn_org (
      asn           VARCHAR(32) NOT NULL COMMENT 'ASN，形如 AS4134，与 link_report.source_asn 同一写法',
      org_name      VARCHAR(64) NOT NULL COMMENT '首次反查到该 ASN 时 ipwho.is 给的组织名（connection.isp），只做展示；最长 64 字符，超长截断',
      first_seen_at DATETIME    NOT NULL COMMENT '首次见到（UTC）',
      PRIMARY KEY (asn)
  ) COMMENT = 'ASN 到展示名的映射：运营商维度以 ASN 做键，名字只做展示，避免上游文案漂移裂列';
  ```
  `SchemaMigrationTest` 相应改：三张表的列/注释/唯一键非空断言换成 `asn`，新增 `asn_org` 断言。

**ingest**（`LinkReportServiceImpl`）：
- 反查成功：`report.setSourceAsn(info.asn())`；若 `info.isp()` 非空则 `asnOrgRepository.insertIfAbsent(asn, truncate(isp), now)`（首次见到的名字，之后不覆盖）。反查失败：`source_asn` 留 null，不动 `asn_org`。
- `IpAsnClient.ISP_MAX_LENGTH`/`truncateIsp` 保留，语义改为「展示名列宽」，注释指向 `asn_org.org_name`。

**归档 / 告警 / 查询**：
- `LinkReportArchiveService.keyOf`：`asn = report.getSourceAsn() == null ? "" : report.getSourceAsn()`。
- `LinkReportRepository` / `LinkReportDailyRepository` 的三个聚合方法与投影 record：`isp` → `asn`（`GROUP BY ... source_asn` / `asn`），Java 侧空串归一成 null 的做法不变；方法名改 `aggregate…ByDomainAndAsn`。
- `LinkReportAlertService`：去重键 `(userId, domain, asn)`；ASN 级判定跳过 `asn == null` 的行（理由不变：未知归属的告警不可行动）；推送前查 `asn_org` 取展示名，查不到就用 ASN 串。`NodeNotifyService.notifyIspDegraded` 改名 `notifyAsnDegraded(userId, email, domain, asn, orgName, rate, samples)`，卡片字段「运营商」显示 `orgName`（空则 ASN 串）并另加一行「ASN」。
- `AdminLinkHealthServiceImpl`：按 `(domain, asn)` 合并两表；一次 `asnOrgRepository.findAll()`（几十行量级）把名字带上。

**管理端契约**（`LinkHealthResponse`）：`IspCell` → `AsnCell(asn, orgName, samples, aliveCount, successRate)`，`asn` 空串 = 反查失败，`orgName` 可空 = 还没见过展示名。`DomainRow.isps` → `asns`。前端 `types.ts` 同步；`LinkHealthView.vue` 显示优先级 `orgName` → `asn` → 「未知运营商」（`asn === ""`），列头改「运营商（ASN）」。

**新增仓储**：`AsnOrgRepository { void insertIfAbsent(String asn, String orgName, Instant now); Map<String, String> findAllNames(); }`，MyBatis-Plus 实体 `AsnOrg`（`entity/`），`INSERT IGNORE` 实现。`DatabaseFixtures.clearAll` 加 `asn_org`。

**测试**：
- 现有 `insertWindow(..., isp, ...)` 夹具改成 `setSourceAsn`。
- `LinkReportEndToEndTest` 补：同一 ASN、两次反查返回不同文案 → 矩阵只有一列、名字是首次那个、告警只推一次。
- `AdminLinkHealthServiceImplTest`：`orgName` 缺失时 `asn` 照常返回。

### 3.2 告警去重过期

**现状**：`evaluate` 里 `alerted=1` 就永远去重，直到出现一段 ≥ 最小样本量且成功率达标的健康窗口清档。用户在劣化中离线（最常见：链路差到断开），回来仍劣化不再推。

**设计**：新配置 `link-report.alert-dedup-ttl`（`Duration`，默认 `24h`）。`evaluate` 中 `previouslyAlerted` 的判定改为 `alerted && alertedAt != null && alertedAt.plus(ttl).isAfter(now)`；过期视同未告警：仍劣化就重推并把 `alertedAt` 刷成 `now`。恢复清档逻辑不变。不加列、不加迁移、不清理行（维度有界）。

**测试**（`LinkReportAlertServiceTest`）：过期后仍劣化 → 再推一次且 `alerted_at` 更新；未过期 → 不推；重启（`newService()`）后同样按落库时间判。

### 3.3 调度线程池

**设计**：`application.yaml`（主配置，属应用级基础设施，不是可选模块默认值）加
```yaml
spring:
  task:
    scheduling:
      pool:
        size: 2
      thread-name-prefix: sched-
```
`SchedulingConfig` 类注释更新为当前 5 个任务与默认周期。新增 `SchedulingConfigTest`：从上下文取 `ThreadPoolTaskScheduler` 断言 `getPoolSize() == 2`。

### 3.4 ASN 反查缓存配置化

**设计**：新增 `config/IpAsnCacheProperties`（`@ConfigurationProperties(prefix = "ip-asn-cache")`：`ttl` 默认 `24h`、`maxEntries` 默认 `5000`），`application.example.yml` 加带注释的段。`CachingIpAsnClient` 增加 `(delegate, clock, ttl, maxEntries)` 构造器，原双参/三参构造器委托到它；`DnsConfig.ipAsnClient(RestClient, Clock, IpAsnCacheProperties)` 用配置装配。测试：`CachingIpAsnClientTest` 补一条 TTL 可配（1 分钟 TTL 过期即重查）。

## 六、已知取舍

1. **`asn_org` 只记首次名字**：ipwho.is 文案改了不跟。展示名的目的只是让人认得出，稳定比新鲜重要；要改名字手工改一行。
2. **去重过期 24h 未经实测**：与三期其它阈值同样理由，配置化以便回退。
3. **采样周期仍是「30 秒 + 整轮探测耗时」**（三期终审 Minor 7）：本期不并发化，样本数在最坏情形下每窗口每节点 6 个而非 10 个，服务端最小样本量 20 与 15 分钟回看在 K=3 时仍够。
4. **心跳循环的 `select!` 一行仍无单测**：能测的逻辑已全部挪进 `plan_heartbeat`。
